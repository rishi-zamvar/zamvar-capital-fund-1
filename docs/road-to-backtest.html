What's needed to run the 1-year backtest, calibrate per stock, and build playbooks

Five stages from where we are to a real, calibrated, playbook-backed strategy. The honest split: the backtest itself is nearly a data pass away — the machinery exists — but the per-stock fine-tuning and playbooks (the actual edge) are genuinely new work, and the data is thinner than it looks.

BUILT exists today · MOSTLY — a run away · NEW — real work

1 Assemble the historical event set

Historical catalysts + prices over the window MOSTLY — a run away

The raw material: every past catalyst in the window + the price action around it, point-in-time, survivorship-free.

  • Prices — multi-source cross-checked ingestion is built (6.9/6.10); ingest 1–2 yr of weekly bars for the 19 names
  • Trial readouts — CT.gov, flowing + verifying (authoritative single source)
  • Earnings — Nasdaq calendar, free
  • PDUFA/AdCom — our own EDGAR-8K tracker (6.11); it found forward events — now run it over the *past* year (a historical efts pass) to pull past PDUFA 8-Ks + dates
  • The run: one historical-ingestion pass populates the store; build_event_set (already built, Phase 7) assembles it — point-in-time, delisted-inclusive, no look-ahead

2 Run the Layer-A backtest

Mechanical baseline + honest go/no-go BUILT

The trustworthy number: deterministic replay, pessimistic fills, no AI in the loop.

  • The harness exists (Phase 7) — run_layer_a replays the corrected weekly strategy with gap-open fills, producing win rate, avg win/loss, Sharpe, Sortino, max drawdown, hedge-effectiveness
  • The sample-based gate — too few events = automatic no-go, no matter how good the numbers look (it refuses to flatter a thin sample)
  • Just point it at Stage 1's event set and read the first real baseline — this is the "have we done our backtest" answer

3 Fine-tune the assumptions — per stock / per cohort

Fit the model parameters from realized outcomes NEW — real work

This is the moat. The tools are commodities; the edge is calibrating their assumptions against what actually happened.

  • The seam exists — Phase 5 built load_params: tools read a top-confidence "fitted params" row, falling back to bootstrap defaults. The refit was deliberately deferred to here.
  • Compute the realized outcome per event (the actual +/- move around each catalyst, from the price bars)
  • Fit, per stock and per cohort: the catalyst move distribution (the +/- estimate), the base rates (phase-transition LoA, drop-classifier reversal, AdCom follow-through), adaptive SL/TP levels, IV-crush, and the hedge payoff matrix
  • Store as versioned, confidence-scored fitted_params — which the live desk then reads automatically. Refit as new outcomes land.

4 Build the playbooks

Write per-stock scenarios + outcomes into the knowledge base NEW — real work

So the live desk can ask "what happened last time a name like this had a catalyst like this?"

  • The KB exists (Phase 2) — SQLite + vector search, playbook/outcome nodes, cite-or-drop, and analog_query that retrieves nearest past scenarios with their outcomes
  • The record seam exists — Phase 6.5 writes weekly outcomes back as cited KB claims
  • Populate it from history: turn each backtested event + its outcome into a per-stock/cohort playbook entry — the pattern, the base rate, what worked, confidence, and the source citation
  • Result: analog_query returns real analogs (not bootstrap stubs) to every analyst on every live catalyst

5 Close the loop

Predict → realize → score → refit, without overfitting NEW — Phase 10

The desk gets measurably better each week — and can never quietly reward-hack the money path.

  • The learning loop (roadmapped as Phase 10): score every resolved prediction vs. realized, propose a parameter diff, and gate it behind golden-set regression + walk-forward evaluation so a change must prove out-of-sample before it ships
  • The paper ledger (Phase 8) is the forward out-of-sample test that feeds this — the month-long proof before real capital

! The honest constraint you should know going in

1 year × 19 names is thin data — per-stock fitting will be data-starved

Biotech catalysts are sparse per name: a single stock might have 1–3 real catalysts in a year. You can't fit a trustworthy per-stock move distribution from 2 events. The sound approach: fit at the cohort level (catalyst-type × therapeutic-area × drop-regime), then apply per-stock adjustments only where a name has enough history. And pull a multi-year window (3–5 yr — the free pipeline supports it, delisted names included) for real statistical power. "Assumptions are the moat" only holds if the assumptions are calibrated on enough realized outcomes to be trusted — so the backtest window and the fitting granularity are themselves money-critical choices.

▸ The sequence, and what each stage costs

Stage 1–2
One focused phase — historical ingestion pass + run the harness. Gets you the first real baseline + go/no-go.
Stage 3–4
The calibration phase — fit params + build playbooks from the backtest outcomes. The moat; the biggest new build.
Stage 5
Phase 10 — the gated learning loop, running continuously once paper trading (Phase 8) is live.

Everything in Stages 1–2 is buildable now on free data (plus the multi-year-window choice). Stages 3–5 are where the real intellectual work is — and where the edge, if there is one, gets made and proven honestly.
