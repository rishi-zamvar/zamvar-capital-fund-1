The Warm Playbook

A retrievable, cited catalogue of every past peer-universe catalyst — what happened, WHY, and what to watch — that turns raw events into the analog context the models reason with. Built with hindsight; leak-guarded at retrieval.

This is the project's core: it promotes the analog method in the move-estimator from cold weight 0.5 to warm weight 1.0 — i.e. the models start reasoning from real precedent instead of priors. Everything below is grounded in the 3 research streams + our actual data.

Scope measured, not guessed

73peer names
336peer catalysts
218binary core (pdufa+readout)
258have move + text
118peer earnings (optional)

Core = 23 PDUFA + 195 readouts. Gaps handled honestly (never fabricated): 46 month-precision readouts (text-only, move=null), 55 with no exhibit (CT.gov+move or skip), 8 naked (skip). AdCom has zero history (forward-only) — its taxonomy applies live, not in the backfill.

1What goes in it — the schema

Each past catalyst becomes one cited KB node (reusing the shipped kb.py scaffold), with three layers:

catalyst node (insert_claim -> cited)
  filterable:  type · ticker · indication · knowable_asof · outcome_label
  outcome:     move (SIGNED) · label · confidence · move_consistency_flag   [RESULTED_IN edge]
  drivers:     { PDUFA: adcom_vote, pivotal_strength, endpoint_acceptability,
                        safety_signal, prior_crl, cmc_readiness, review_division,
                        class_precedent, expedited_designation, label_risk
                 READOUT: prior_ph2_effect_size, endpoint_type, powering,
                        class_precedent, mechanism_validation, population, prior_interim }
  watch:       implied_move · IV_crush · financing · short_interest · run_up ·
               options_flow · insider · mgmt_tone · FDA_comms · competitor_reads
  retrieval_text: "{type} catalyst for {ticker} ({indication}): {one-line setup}"  -> embedded
  CITES -> the 8-K/CT.gov evidence source

Plus generalization nodes (insert_playbook): per scenario_type — e.g. pdufa|prior_crl=cmc, ph3_readout|surrogate_endpoint — a base-rate + driver-adjustment summary cited from the catalysts it generalizes. The playbook is a base-rate + driver-adjustment engine, not an oracle; weights are refittable priors, never hardcoded laws.

2How it's built — the attribution pipeline

per catalyst:  CIK-filter exhibits (drop 41% cross-company contamination)
  → bundle: own-company 8-K/PR text + CT.gov status + SIGNED move
  → 1 LLM call → structured JSON {outcome, label, drivers, watch, confidence, citation}
  → insert_claim (cite-or-drop, idempotent on catalyst_id+hash)
then: aggregate per scenario_type → insert_playbook base-rate+driver summaries
  • Outcome anchoring differs by type: PDUFA = signed move is primary truth, text corroborates (the lake skews to acceptance PRs, not decision-day 8-Ks); readouts = text is primary, move corroborates.
  • Consistency cross-check: if text says "approved" but the stock fell, set move_consistency_flag + lower confidence — never silently trust one side.
  • One-time cost for ~218 catalysts: ~$2 (Haiku) to ~$7 (Sonnet). Fully cached/offline inputs otherwise.

3How models pull from it — retrieval

  • analog_query(local bge-large embedder, context, filters, k) → structural filter (type always; +indication when the cohort stays ≥5) → cosine nearest-neighbors → attaches each analog's outcome.
  • Analogs flow into the football-field estimator (analogs → signed up/down move split → aggregator). Populating the playbook flips that analog leg 0.5 → 1.0.
  • The model receives a structured "updated context" block: the top-k precedents with their outcome, signed move, drivers, and what-to-watch — each with a citation.

4How we identify what happened — outcome attribution

Covered by the pipeline in §2: the LLM reads the company's own announcement, the CT.gov status, and the signed price move together; the move/text consistency check guards each label; cite-or-drop means no label exists without its source. Month-precision or exhibit-less catalysts get a null move / text-only label or are skipped — flagged, never invented.

5No-look-ahead (the one correctness guarantee)

The playbook is built with hindsight — that's allowed. But at retrieval time (backtest or live) it must only return catalysts knowable as of the decision. Fix: stamp each node with knowable_asof, add one filter clause to analog_query, thread the cutoff, and ship a dedicated leak test. Small, and non-negotiable.

Decisions for your sign-off

  • Extractor model — Sonnet (~$7, sharper attribution on messy filings) vs Haiku (~$2). One-time money-path build.
  • Earnings tier — include the 118 peer earnings as context too, or keep the playbook to the 218 binary catalysts?
  • Driver depth — the full ~18-field taxonomy (recommended — it's the meat), or a lean core subset?
