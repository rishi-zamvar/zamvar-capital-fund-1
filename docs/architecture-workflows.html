The Catalyst Desk

A biotech event-driven trading firm run by agents. Three workflows, one GP on top: predict the catalyst, build the week's hedged portfolio, then diligence it independently — every claim sourced, every number computed by a tool.

GP / MD (Fable) & risk-desk agent bull bear deterministic tool / feed monitor / guardrail knowledge base
ORG

The firm, top to bottom

The MD/GP (a Fable agent) presides over all three workflows and is the only voice the LP (you, via the iOS app) talks to. The knowledge base feeds every workflow and learns from every realized outcome. No trade reaches the market without passing the human gate.

W1

Catalyst Call

Runs once per imminent catalyst (T-2 to T-1). Four analysts pull sourced signal; a bull and a bear build opposing cases in isolation and debate for bounded rounds; a manager synthesizes a single binary verdict. Pure prediction — no sizing, no positioning here.

IN: ticker + catalyst (from the calendar monitor)  ·  OUT: CatalystCall {direction ↑/↓, confidence, falsification criteria}

W2

Portfolio Construction

Takes the week's set of calls and turns them into one hedged portfolio. The trade builder picks the inverse-hedge peer; the risk desk re-validates the hedge and sizes for survival; the MD/GP fits it to the whole book and signs off.

IN: week's CatalystCalls  ·  OUT: WeeklyPortfolio + StrategyDossier (for diligence → LP)

W3

Independent Diligence

A firewalled second opinion on the proposed portfolio. It receives only {ticker, catalyst, pair} — never Workflow 1/2's thesis — and rebuilds the case from raw sources across independent dimensions, adversarially trying to break the trade before capital touches it.

IN: {ticker, catalyst, pair} only (firewall)  ·  OUT: DiligenceDossier {go / no-go, evidence, residual risks}

The knowledge base, the monitors, and the learning loop aren't a workflow — they wrap all three. This is what makes the desk auditable and self-improving.

Learning loop

After each catalyst resolves: score prediction vs. reality, run an LLM-judge calibrated to your graded labels, and propose a playbook/config diff — but only merge it if it passes a golden-set regression replay. That gate is what makes "gets better" real instead of drift.
