# Phase 06.8 Plan 02: Stage-1 Deterministic Scanner Summary

The $0-LLM Stage-1 trigger: `SCAN_PARAMS` (the single, missing-key-raising threshold dict), `build_card` (write-once company card assembled point-in-time from `bars_asof` + injected raw provider values + the embedded `thesis_scan` row, recomputing no quant number), and `delta_card` (the pure F1-F13 week-over-week transition engine with latching, hysteresis, cadence honesty, and the PRINCIPAL/CORROBORATOR `_wakes` gate) — the layer that decides who earns a Haiku pass, and that an LLM can never touch.

## What Was Built

**Task 1 — SCAN_PARAMS + build_card.** New module `desk/company_scan.py`. `SCAN_PARAMS` is the module-level threshold dict read by direct subscript (missing-key-raises, no `.get`), deliberately decoupled from the KB fitted-params seam (mirrors `DILIGENCE_PARAMS` L31-35). `build_card(conn, ticker, week_end, raw, thesis_row, *, params)`:
- derives price/vol (ret_1w/ret_4w/px_vs_ma4/px_vs_ma12/sigma5/sigma20/turnover_flag/vol_vs_median) from `bars_asof(conn, ticker, week_end)` — week_end <= as_of, no look-ahead;
- pulls options/positioning/balance-sheet fields from the injected `raw` dict, reusing `diligence.options_liquid`/`zero_liquidity` (no re-derivation) and `_runway_band` from the params edges;
- embeds `thesis_row` verbatim under `card["thesis_row"]` + its ref under `card["thesis_ref"]` (calls no `classify_drop`/`weekly_base_rate`/`thesis_scan`);
- carries the prior card's `fired` latch dict forward via `card_asof(conn, ticker, _prior_week(week_end))`.

**Task 2 — delta_card + _wakes.** `delta_card(prev, cur, *, params)` is pure (no conn/LLM/network); it implements F1-F13 exactly per the flag catalog, every threshold a `params["scan"][...]` subscript, no numeric literals in the rule bodies. Two reusable helpers (`level_up`/`level_down`) carry the latch + hysteresis re-arm (`threshold*(1±rearm_frac)`); F6/F8 are cadence-gated to a fresh settlement/runway datum; F1 latches per band; F12/F13 read only the embedded thesis row. `_wakes(tripped, params)` wakes on any PRINCIPAL or >=2 CORROBORATORs (a lone CORROBORATOR never wakes) from the frozen `_TIER` map.

## Deviations from Plan

### Auto-added Missing Functionality

**1. [Rule 2 - Missing critical param] Added `offering_s3_ret` to SCAN_PARAMS**
- **Found during:** Task 2, implementing F9 (offering_signal).
- **Issue:** The flag catalog specifies F9 fires on a "new S-3 while ret_4w > +20%", but the plan's frozen SCAN_PARAMS omitted any key for the +20% threshold. Inlining `0.20` would violate the SCAN-03 no-numeric-literals / no-silent-fallback invariant the plan mandates.
- **Fix:** Added `"offering_s3_ret": 0.20` to SCAN_PARAMS and read it via direct subscript, keeping the money-invariant intact.
- **Files modified:** src/catalyst_trader/desk/company_scan.py
- **Commit:** 275e580

### Minor ponytail choices (in scope)

- `build_card` imports only `bars_asof`/`card_asof` from store (not the unused `write_card` the plan listed — Plan 03 imports it where it writes).
- The form codes (`424B5`/`FWP`/`S-3`) are module-level string constants (`_OFFERING_FORMS`/`_S3_FORM`) — grammar, not thresholds — mirroring the `_TIER` map.
- Reproducibility test builds fresh input copies per call (delta_card intentionally mutates `cur["fired"]` in place as its latch output, so "same state -> same fires" is asserted on fresh state, not by re-running on a mutated dict).
