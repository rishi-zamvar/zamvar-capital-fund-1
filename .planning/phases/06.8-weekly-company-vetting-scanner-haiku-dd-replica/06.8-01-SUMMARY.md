# Phase 06.8 Plan 01: Company-Card Store + Scan Contracts Summary

Write-once point-in-time company-card store (migration 006 + four store fns mirroring `upsert_bars`/`bars_asof`) plus the two new scan contracts — the `ScanInput` typed firewall and the rich gap-not-answer `OpportunityFlag` — the data substrate and type facts every later 6.8 plan binds to.

## What Was Built

**Task 1 — Migration 006 + four store functions.** `006_company_card.sql` adds `company_card` and `scan_flag`, both `UNIQUE(ticker, week_end)` with a single JSON TEXT payload column, mirroring `005_price_bars.sql` (auto-applies through the existing `db.migrate` glob loader, zero code change). Four store fns appended verbatim to the `upsert_bars`/`bars_asof` pattern (SELECT-then-UPDATE-else-INSERT, try/commit/except-rollback):
- `write_card` / `card_asof` — write-once card; `card_asof` returns the single latest card with `week_end <= as_of` (the money-critical no-look-ahead guard), None before the earliest.
- `write_scan_flag` / `scan_flags_asof` — the audit ledger; idempotent per (ticker, week_end), `routed` stored 1/0, `scan_flags_asof` reads payloads `week_end <= as_of`.

**Task 2 — ScanInput firewall + OpportunityFlag.** Both `extra="forbid"`, appended to `contracts/__init__.py`:
- `ScanInput` carries ONLY {ticker, week_end, card_prev, card_cur, tripped}; any desk artifact is a `ValidationError` (mirror of `DiligenceInput`).
- `OpportunityFlag` — fixed 8-value `opportunity_type` (incl. `no_opportunity`) + 4-value `verification_needed`, reuses `KeyFinding`, carries `thesis_to_verify` + `unknowns`, and exposes NO `direction`/`size`/`target`/`route` field. `to_weekly_flag` deliberately deferred to Plan 03 (md.py stays untouched).
