<decisions>
## Implementation Decisions (LOCKED — from free-data-pipeline.md research + operator + shakedown finds)

### 1. Adopt edgartools (operator-approved 2026-08-16) — the ONE new dep
SEC XBRL fundamentals/float/cash-runway/Form-4/13F via `edgartools` (MIT, keyless, `set_identity(email)` for the SEC UA). REPLACES + upgrades the hand-rolled `edgar.py` (also fixes the shakedown's "no CIK for TICKER" gap — edgartools resolves CIK internally). Fills the #1 known free-data weak spot (float). Provenance-tagged, degrade-safe.

### 2. FRED macro provider — no new dep
`providers/fred.py` (plain httpx, free instant key via `settings.fred_api_key`): rates (DGS10/DGS2/T10Y2Y), FEDFUNDS, VIXCLS (free VIX history), CPI. Fills the macro/regime gap (currently zero coverage). Degrades to skip when key absent.

### 3. Always-on daemon = launchd + stateless run_cycle() (thin — launchd IS the supervisor)
`scripts/daemon.py::run_cycle()` = one full pass then exit: for each source due (per the cadence table) fetch → snapshot → UPSERT via existing store paths → detect_gaps() → write `.monitor/data_health.json`. launchd `StartInterval` + `KeepAlive`-on-failure = supervisor + crash-recovery; store idempotency = resumability. NO long-lived loop, NO queue, NO new infra. Cadence table (accuracy-first, NOT low-latency): prices daily-after-close, CBOE 1-2x/day, FINRA on-publication, catalysts daily, XBRL weekly, FRED daily.

### 4. Self-heal + N-source median (accuracy is the priority — lean in)
Gap-detector (missing name-weeks / stale / missing cards) → backfill through the same ingest path. Dead-source detection → the cascade already fails over. Upgrade the price cross-check from 2-source-pairwise to **N-source median/majority-vote** (robust to one bad source in ≥3); still NEVER impute. Split/bad-tick/stale detectors.

### 5. Raw-snapshot lake (audit + re-parse)
Every fetched response → `data/raw/{source}/{yyyy}/{mm}/{ticker}_{fetch_ts}.json` (`.html` for scrapes); `raw_snapshot_path` on persisted datums. Re-parse without re-fetch. Size-capped + monthly prune. $0 local disk.

### 6. Data-health → the existing monitor
Daemon writes `.monitor/data_health.json` (per-source last_success/consec_fail/degraded, coverage %, stale list, gap counts, divergence count); `monitor/server.py` renders it in a data-health tab; alert on degradation/coverage-drop/divergence-spike (optionally a ZeeChat ping).
