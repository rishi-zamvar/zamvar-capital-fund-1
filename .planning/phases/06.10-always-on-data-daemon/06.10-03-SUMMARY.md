# Phase 06.10 Plan 03: Raw-Snapshot Lake + get_text(json_body=) Transport Summary

Every successful `_http` fetch now archives its raw response to `data/raw/{source}/{yyyy}/{mm}/{key}_{fetch_ts}.{json|txt}` as a side-effect, retrievable via `snapshot_path()` for `raw_snapshot_path` provenance and re-parseable offline via `load_snapshot()`; the lake is bounded by `prune_snapshots()` (age/size) and `$0` local disk; `get_text` gains a `json_body=` POST-text passthrough so FINRA's NDJSON Query API works in Plan 05.

## What shipped

**Task 1 — raw-snapshot lake (PIPE-06)** (`acc3b99`, test `044e790`)
- `_write_snapshot()` fires at the success point in `_fetch` (after `raise_for_status`), archiving `resp.text` to `data/raw/{source}/{yyyy}/{mm}/`. It returns *before* this on both degrade (`except _DEGRADE -> return None`) and cache hit (`return hit[0]`), so a degraded `None` writes nothing and an in-TTL repeat does not double-write.
- `snapshot_path(source, url, *, kind, params, json_body)` recomputes the cache-key and returns the last written path (or `None`) — providers record it as `raw_snapshot_path`.
- `load_snapshot(path)` re-parses an archived file with zero network (`.json -> json.loads`, else raw text) — the audit/re-parse lever.
- `prune_snapshots(max_bytes=, older_than_days=)` bounds the lake oldest-first.
- Base dir is `settings.raw_snapshot_dir` (env `RAW_SNAPSHOT_DIR`, default `data/raw`), so tests use `tmp_path`.

**Task 2 — get_text(json_body=) passthrough** (`0c01474`, test `d9c482f`)
- One-line forward of `json_body` into `_fetch("text", ...)`; `_fetch` already POSTs when `json_body` is set and returns `resp.text` for `kind=="text"`. GET-only callers unaffected. The capture test proves the body is POSTed and raw text returned.
