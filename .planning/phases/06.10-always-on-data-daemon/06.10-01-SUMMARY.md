# Phase 06.10 Plan 01: edgartools Fundamentals/Float Provider Summary

Rewrote `providers/edgar.py` onto **edgartools 5.49.0** (the one operator-approved new dep): `fetch()` now resolves the CIK internally via `edgar.Company(ticker)` — closing the 6.9 shakedown's "no CIK for TICKER" gap (21 names) with ZERO change to build_card's `seen_accessions`/`live_shelf` contract — and a new `fundamentals()` emits `shares_outstanding` + `cash_runway_months` from standardized XBRL facts, filling the free-data float/runway gap.

## What Was Built

- **`edgar.fetch(ticker)`** (rewritten, CIK-internal): `edgar.Company(ticker).get_filings(form=[424B5,FWP,S-3,S-3ASR])` → `seen_accessions` (list of `{accession, form, filing_date}`) + `live_shelf` (exact-match S-3/S-3ASR) + green provenance. Dropped the `cik` param and the hand-rolled `data.sec.gov/submissions` GET. Contract keys byte-identical to what `build_card` consumes.
- **`edgar.fundamentals(ticker)`** (new): standardized facts `common_shares_outstanding`, `cash_and_equivalents`, `operating_cash_flow` via `facts.get_concept(name, return_metadata=True)`. `cash_runway_months = cash / monthly operating burn` (OCF over its YTD period). Point-in-time provenance carries the freshest fact's `filing_date`; `source_url` = the SEC companyfacts API.
- **Degrade-not-raise** on both: unknown ticker / edgartools error / no filings / no usable facts → `None`. The one legit `RuntimeError` is a missing `settings.sec_user_agent` (config error, matching `_http`'s UA rule — never an empty UA to SEC).
- **`edgartools==5.49.0`** added to `pyproject.toml` — the ONLY new dep (PIPE-08). No new config field (reuses `sec_user_agent`).

## edgartools Introspection Findings (the mock is pinned to these REAL names)

Ran against the INSTALLED edgartools 5.49.0 before writing any fixture/mock (the anti-yfinance-MultiIndex guard):

**Filings (Task 1):**
- `edgar.set_identity(ua: str)` — module-level.
- `edgar.Company(ticker)` → `Company`; `.cik` is an `int`; unknown ticker raises `edgar.CompanyNotFoundError`.
- `c.get_filings(form=[...])` → `edgar.entity.filings.EntityFilings` — iterable, `len()`, indexable. edgartools **prefix-matches** the form list (so `"S-3"` also pulls `S-3/A`).
- each item `EntityFiling`: `.accession_no` (str, e.g. `"0000320193-26-000018"`), `.form` (str), `.filing_date` (`datetime.date`).

**Fundamentals (Task 2):**
- `c.get_facts()` → `edgar.entity.entity_facts.EntityFacts`.
- `facts.get_concept(concept_name, period=None, unit=None, return_metadata=False)` → a **float** by default, or (with `return_metadata=True`) a **dict**: `{value, tag_used, period ('2026-Q3'), period_end (date), filing_date (date), unit, concept_name, synonyms_tried}`, or `None`.
- standardized concept names (from `facts.list_supported_concepts()`): `cash_and_equivalents`, `operating_cash_flow`, `common_shares_outstanding` (plus `capex`, `free_cash_flow`, `net_income`, etc.).
- `get_concept` does synonym resolution across us-gaap tags (`synonyms_tried`) — chosen over `query().by_concept('us-gaap:...')` (which needs a raw tag, more fragile).

The fixture (`tests/fixtures/edgar_facts.json`) and the fakes (`_FakeFiling`/`_FakeFacts`/`_FakeCompany`) mirror exactly these attribute/method names and return types — no guessed flat-JSON shape.
