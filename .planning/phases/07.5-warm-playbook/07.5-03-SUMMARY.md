# Phase 07.5 Plan 03: Warm-Playbook Attribution Front-Half Summary

**A pure, offline, fixture-tested extraction unit that turns one past peer catalyst into a cited, cross-checked CatalystRecord from cached lake material — CIK-filtering cross-company exhibits first, anchoring PDUFA outcomes to the signed move, and isolating the live LLM behind an injected complete_fn.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 3/3
- **Files created:** 4
- **Tests:** 14 new (all pass), full suite 1373 passed

## Accomplishments

- **cik_filter_exhibits** — parses the CIK from each exhibit URL's `/data/<CIK>/` segment and keeps only the catalyst's own company, dropping the 41%-of-peers cross-company contamination (LPCN↔Acumen style) before any text is read.
- **build_bundle** — assembles the event-proximate bundle (CIK-filtered own-company exhibit text, ctgov presence, SIGNED realized move + window + knowable_asof, profile indication/modality, date precision) from cached material only, with own_cik/lake_dir/profiles injectable for offline tests.
- **extract_record(bundle, complete_fn)** — parses the injected completion, drops uncited drivers (cite-or-drop), overwrites deterministic facts from the bundle, applies PDUFA move-primary / readout text-primary anchoring, lowers confidence on move/text disagreement or month-precision, and returns None for a naked catalyst (never calling the LLM).
- **build_prompt** — the extraction prompt embedding the research-A driver taxonomy + strict JSON schema + anchoring rules, with the static taxonomy cached across calls (no model call here).

## Deviations from Plan

### Auto-fixed / Improved

**1. [Rule 1 - Correctness] Lake join uses the reproduced `_safe_name` stem, improving on the plan-check NIT's proposed last-segment glob**
- **Found during:** Task 3 (verifying the plan-check NIT 1).
- **Issue:** The NIT correctly flagged that `_safe_name` hashes the FULL fetch key so the filename can't come from the URL alone, and proposed globbing by the sanitized last path segment (`ex99-1.htm_*`). But empirically that last-segment is a heavy cross-company collision in the lake (dozens of different companies' `ex99-1.htm`), which a last-segment glob + closest-date CANNOT disambiguate.
- **Fix:** edgar_8k exhibits are fetched with NO params and NO json_body (`get_text("edgar_8k", url, ua="sec")`), so the 8-char hash `sha1(f"{url}()None")[:8]` IS reproducible from the source_url alone. build_bundle reproduces the exact stem via `_safe_name(_key("text","edgar_8k",url,None,None))` then globs `"<stem>_*.txt"`. Verified against real files: KRYS `9663e785`, LPCN-own `fb354291`, Acumen `be57e147` each resolve to exactly one correct file.
- **Files:** src/catalyst_trader/playbook/extract.py, tests/test_playbook_extract.py
- **Commit:** 42bf4f8

**2. [Rule 3 - Data reality] `catalyst_move.realized_move` is already SIGNED in the live DB (261 of 468 rows negative)**
- **Found during:** Task 3 investigation.
- **Issue:** `discover.py:480` documents/writes `abs(...)`, which would make PDUFA anchoring degenerate (every PDUFA would look like an approval). The plan and plan-check both assumed realized_move is signed.
- **Resolution:** The live `catalyst.db` already holds signed moves (min −0.93, max +7.53; LPCN 964 = −0.281, KRYS 271 = +0.052), so build_bundle reads `realized_move` directly as the signed move — the plan author was right. The stale `abs()` in the backfill is superseded by a signed write path and is out of this plan's scope (extract.py only); the median/volatility readers already defensively `abs()`, so nothing downstream breaks. No discover.py change made.
