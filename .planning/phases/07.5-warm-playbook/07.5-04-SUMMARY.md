# Phase 07.5 Plan 04: Warm-Playbook Attribution Back-Half Summary

**A cite-or-drop KB writer that persists one leak-safe analog per catalyst (catalyst node + outcome node + RESULTED_IN + CITES on both + a single card-embedding vector) idempotently through kb.insert_claim, guarded against populate/query embedder drift, plus the --run-gated one-time script that populates the resolved peer corpus cache-first with the local embedder.**

## Performance

- **Duration:** ~6 min
- **Tasks:** 3/3
- **Files created:** 3
- **Tests:** 14 new (all pass); full suite **1387 passed**

## Accomplishments

- **insert_catalyst_record** — writes one `catalyst` node (structural-filter keys top-level, incl. the `knowable_asof` leak stamp) + one `outcome` node (label + SIGNED `move` + confidence) + a `RESULTED_IN` edge + `CITES` on both, all routed through `kb.insert_claim` in one transaction (cite-or-drop; no raw `kb_node` SQL). The catalyst node carries the only vector — `hash_embed`/`local_embed` of `compose_card(record)` — proven byte-equal in a test.
- **Idempotency** — keyed on `(ref_id, content_sha)` (sha256 over `model_dump_json`): an unchanged re-run returns the existing id (no dup), a content change writes a fresh node. Makes the ~$7 populate safe to resume after a crash.
- **assert_embedder_consistency** (plan-check NIT 2) — stamps the embedder `__name__` on every catalyst node and refuses to (a) grow a corpus with a second embedder or (b) let the warm-retrieval path query with a mismatched embedder — closing the silent hash-populate/fastembed-query KNN-corruption hole. Three tests cover it.
- **scripts/build_playbooks.py** — the one-time populate: dry-run default counts the corpus by tier (268 binary CORE = pdufa+trial_readout, 200 EARNINGS) offline with a token/$ estimate and no spend; `--run` gates the live Sonnet seam; cache-first `build_bundle -> extract_record -> insert_catalyst_record` with `kb.default_embedder()`, idempotent + resumable, skip-reasons + move_consistency flag tallied.
- **Warm-path proof** — after populating ≥ min_analogs of a type, `analog_query` returns real analogs whose `outcome.move` is present and SIGNED, and `catalyst_move_estimate` reports `cold_start: False`.

## Deviations from Plan

### Data reality (documented, no code corner cut)

**1. [Rule 3 - Data reality] Peer-corpus counts are 268 core + 200 earnings, not the plan's 218 + 118**
- **Found during:** Task 3 (dry-run against the live `catalyst.db`).
- **Issue:** The plan/research quoted 218 binary-core + 118 earnings; the live DB has **268** resolved binary-core and **200** resolved earnings catalysts that carry both a realized move and a source URL (the analog-eligibility bar).
- **Resolution:** The 218/118 were research-time estimates; the script selects the corpus by the objective criteria (resolved + has `catalyst_move` + has `catalyst_source.source_url`) and prints the ACTUAL counts rather than fabricating a filter to hit the estimate. The true processable count will be lower still after the naked-catalyst skip (no lake exhibit AND no ctgov AND no move), tallied under `--run`. No corner cut — the honest data-driven count is surfaced in the dry-run.

### Design choices within plan scope

**2. [Rule 2 - Correctness] Embedder guard also fires on the WRITE path, not only the read path**
- The plan-check NIT asked the retrieval/warm path to assert embedder match. Plan 05 owns that path, so `assert_embedder_consistency` is exported for it; additionally `insert_catalyst_record` calls the same guard before writing, so a corpus can't be silently populated with two embedders in the first place. Fully self-contained + tested here.
