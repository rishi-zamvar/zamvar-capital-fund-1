# 07.5 RESEARCH C — KB storage + retrieval architecture (HOW it's stored, HOW models pull)

**Scope:** Design Q2 (build/populate mechanics) + Q3 (retrieval) + the no-look-ahead-at-application
mechanism. Reuses the existing `kb.py` scaffold + migrations 003/004 + the 011 bitemporal / `serving.py`
as-of gateway. **No rebuild** — the schema, write-path, embedder, and vec0 loader are all already in
place. This doc says exactly what rows/edges/vectors to write, confirms the embedder, defines the
retrieval + prompt contract, and specifies the one small addition needed for no-look-ahead retrieval.

Everything below is anchored to real code with `file:line`.

---

## 0. Executive summary (the four deliverables)

1. **Populate-plan** — per past catalyst write: one `catalyst` node (attrs = drivers + the retrieval
   text + a `knowable_asof` stamp), one `outcome` node (attrs = label + signed `move` + confidence),
   a `RESULTED_IN` edge catalyst→outcome, the `CITES`→`evidence_source` edges (mandatory), and one
   `kb_vec` row embedding the catalyst's retrieval-context string. Generalizations = `playbook` nodes
   via `insert_playbook`. All through `insert_claim` (`kb.py:103`) — never raw SQL.
2. **Embedder — DECIDED, no choice left to make.** `BAAI/bge-large-en-v1.5`, 1024-dim, local ONNX via
   `fastembed` (`kb.py:428`, `local_embed` `kb.py:439`). Deps already installed (`fastembed 0.8.0`,
   `onnxruntime 1.28.0`, `sqlite_vec 0.1.9`). vec0 already loads (`db.py:18-20`). Offline hash fallback
   (`kb.py:408`) keeps tests network-free. Recommendation: **keep it. No API embedder.**
3. **Retrieval contract** — `analog_query(conn, embed, context, filters, k)` (`kb.py:172`): structural
   SQL filter → brute-force cosine KNN over `kb_vec` → `_with_outcome` attaches the `RESULTED_IN`
   outcome. The context string embedded is `"{ctype} catalyst for {target}: {verdict.thesis}"`
   (`builder.py:62-63`); filters are `{"type": ctype}` today (`builder.py:113`). Analog moves feed the
   football-field estimator via `_split_moves` (`builder.py:66-72`) → `catalyst_move_estimate`
   (`events.py:51`). Playbooks feed via `load_params`/`query_playbooks` (`kb.py:396`, `kb.py:331`).
4. **No-look-ahead-at-application** — `analog_query` has **NO** time filter today. The minimal fix is
   a one-line `as_of` gate on the catalyst node's `knowable_asof` attr (stamped at populate time from
   `catalyst_move.knowable_asof`). The existing `serving.py` `kb_nodes` gate on `created_at`
   (`serving.py:214-228`) is the WRONG stamp for a hindsight KB — see §5.

## 1. Schema — exactly what exists (migrations 003 + 004)

`migrations/003_kb.sql`:

- **`kb_node`** (`003_kb.sql:4-13`): `id, kind, ref_id, attrs_json, confidence, created_at`.
  - `kind` CHECK enum (`003_kb.sql:6-8`): `company, drug, indication, trial, catalyst, outcome,
    trade, playbook, evidence_source, prediction, hedge_peer`. Mirrored as `_NODE_KINDS`
    (`kb.py:32-37`) and validated at the pydantic boundary (`KBNode._known_kind` `kb.py:59-64`).
  - `ref_id` — optional link to a Phase-1 row (e.g. `catalyst.id`); "don't copy data in"
    (`003_kb.sql:9`). **Use this to point a KB catalyst node at its `catalyst.id`.**
  - `attrs_json` — the kind-specific payload (a JSON string; `KBNode.attrs_json` `kb.py:66-68`).
  - `confidence` — first-class column, used by playbooks/predictions (`003_kb.sql:11`).
- **`kb_edge`** (`003_kb.sql:15-25`): `id, src_id, rel, dst_id, weight, attrs_json, created_at`.
  - `rel` CHECK enum (`003_kb.sql:18-20`): `DEVELOPS, TARGETS, TESTED_IN, ABOUT, RESULTED_IN,
    PLACED_ON, USED_PLAYBOOK, REALIZED, MADE_BY, CITES, ANALOG_OF, HEDGE_PEER`.
  - Indexed both directions: `idx_edge_src(src_id, rel)`, `idx_edge_dst(dst_id, rel)`
    (`003_kb.sql:29-30`).
- **`kb_vec`** — vec0 virtual table. `003_kb.sql:27` created it at `float[384]`; `004_kb_vec_1024.sql`
  **drops + recreates at `float[1024] distance_metric=cosine`** (`004_kb_vec_1024.sql:5-6`). vec0
  dimension is baked into DDL, un-ALTERable, hence the drop/recreate. `kb_vec` is
  `(node_id integer primary key, embedding float[1024])`. `EMBED_DIM = 1024` (`kb.py:27`).

The KB is currently **empty** (0 nodes) — populate is greenfield, no migration or reshape needed.

## 2. POPULATE-PLAN — the exact node/edge/attrs/vector shapes to write

All writes route through **`insert_claim`** (`kb.py:103-129`) — the single write-path that enforces the
cite-or-drop invariant (`kb.py:110-111`: no evidence → `ValueError`, rolls back completely). Do **not**
`INSERT INTO kb_node` directly; that sidesteps the provenance invariant (ponytail note `kb.py:12-13`).

### 2.1 Per past catalyst — the atomic unit

For each of the ~468 signed peer catalysts that have (a) a computable move (`catalyst_move` row) and
(b) attribution source text, write **one transaction group**:

**(a) The catalyst node** — `KBNode(kind="catalyst", ref_id=<catalyst.id>, attrs={...})`:

```python
attrs = {
  # --- structural filter keys (queried via json_extract in _structural_filter kb.py:150-152) ---
  "type": "pdufa",                 # catalyst_type; the filter key builder passes (builder.py:113)
  "ticker": "ARWR",
  "indication": "HoFH",            # from data/universe_profiles.json profile
  "modality": "siRNA",             # from universe_profiles.json
  # --- NO-LOOK-AHEAD stamp (see §5) — copied from catalyst_move.knowable_asof (010:15) ---
  "knowable_asof": "2024-11-18",   # ISO date the T+2 outcome became knowable
  "event_date": "2024-11-15",
  # --- the OUTCOME-DRIVER taxonomy (Design Q1; the "why it happened") ---
  "drivers": {
     "endpoint_met": true, "prior_ph2_effect": "strong",
     "mechanism_precedent": true, "fda_adcom_history": "clean",
     "crl_history": false, "safety_signal": "none",
     "runway_funded_past": true, "competitive_position": "first_in_class",
     "label_risk": "narrow", ...
  },
  # --- pre-catalyst "what-to-watch" tells (Design Q1) ---
  "what_to_watch": ["prior AdCom vote split", "CMC observation history", "runway < 12mo"],
  # --- the text that gets embedded (see §3.1) ---
  "retrieval_text": "PDUFA for ARWR plozasiran (siRNA) in HoFH; endpoint met in Ph3, "
                    "clean AdCom history, first-in-class, funded past catalyst.",
}
```

`attrs_json` is written verbatim by `insert_claim` (`kb.py:114-116`). `json_extract` reads any
top-level key at query time — so **every structural-filter key must be a top-level attr** (nested
`drivers.*` are NOT filterable by `_structural_filter` as written, `kb.py:151`; they're payload the
model reads). `confidence` on the catalyst node is optional; the OUTCOME carries the label confidence.

**(b) The outcome node** — `KBNode(kind="outcome", attrs={...})`, cited:

```python
attrs = {
  "label": "approve",              # enum: approve|CRL for pdufa; hit|miss|mixed for readout; etc.
  "move": 0.34,                    # SIGNED realized move — _split_moves reads a["outcome"]["move"] (builder.py:70)
  "move_window": "(-1,2)",         # matches catalyst_move.move_window (010:16)
  "confidence": 0.9,               # label confidence (Design Q4)
}
```

**CRITICAL contract:** `_split_moves` (`builder.py:66-72`) reads `a["outcome"]["move"]` and splits on
sign (up = `>0`, down = `|move|` for `<0`). So the **outcome attr key MUST be `move` and MUST be the
signed decimal move**. This is the single hard interface between populate and the estimator.

**(c) The `RESULTED_IN` edge** catalyst→outcome — `add_edge(conn, cat_id, "RESULTED_IN", outcome_id)`
(`kb.py:94-100`). `_with_outcome` (`kb.py:156-169`) looks up exactly this edge
(`ORDER BY id LIMIT 1`, `kb.py:160-162`) to attach the outcome to every analog result. Without this
edge the analog returns `"outcome": None` and contributes no move to the estimator.

**(d) Evidence** — `list[EvidenceSource]` (`kb.py:42-49`: `url, retrieved_at, snippet_hash, quote`).
Both the catalyst node AND the outcome node need ≥1 evidence (each `insert_claim` call enforces it).
Sources per catalyst type (frugality: cache-first from the existing lake):
- **PDUFA outcome / CRL:** the announcement 8-K + press release in `data/raw/edgar_8k/` (1920 exhibits).
- **Trial readout hit/miss:** ClinicalTrials.gov results + the readout 8-K.
- **Signed move:** the `catalyst_move` row itself is the numeric provenance; cite its computation.
- Dedup is automatic: `_upsert_evidence` (`kb.py:71-91`) dedups on `(snippet_hash, url)` via
  `json_extract`, so re-citing the same 8-K across many catalysts reuses one `evidence_source` node.

**(e) The vector** — pass `embed=default_embedder()` + `embed_text=attrs["retrieval_text"]` to
`insert_claim`. It writes one `kb_vec` row `(node_id, serialize_float32(embed(text)))`
(`kb.py:120-124`). **Embed the catalyst node only** — outcome/evidence/company nodes need no vector
(analog KNN ranks catalysts). `serialize_float32` from `sqlite_vec` (imported `kb.py:23`).

**Idempotency (Design Q2):** `insert_claim` has no upsert; a naive re-run duplicates nodes. Populate
must be guarded — check `SELECT id FROM kb_node WHERE kind='catalyst' AND ref_id=?` before writing
(pattern mirrors `_get_or_create_company` `kb.py:191-203`). Recommend a populate script that skips a
`catalyst.id` already present, so it's re-runnable like the migrations.

### 2.2 Optional reference nodes (no citation needed)

Company nodes are reference nodes, get-or-created without evidence via `_get_or_create_company`
(`kb.py:191-203`). If you want `DEVELOPS`/`ABOUT` traversal edges (drug/indication/trial nodes), those
kinds exist in the enum but are NOT required for analog retrieval — the estimator only needs
catalyst→outcome. **Ponytail: skip drug/trial/indication nodes for v1** — put indication/modality as
catalyst attrs (they're the filter keys anyway). Add graph nodes only if a multi-hop query emerges.

### 2.3 Per-scenario generalizations — the `playbook` nodes

`insert_playbook(conn, scenario_type, scenario, strategy, confidence, evidence)` (`kb.py:252-265`)
writes a `playbook` node with `attrs = {scenario_type, scenario, strategy}` and first-class
`confidence`, cited (it "cites the outcomes it generalizes from", `kb.py:255-256`).

- **`scenario_type`** is the retrieval key (`query_playbooks` filters on it, `kb.py:333-337`).
- Two distinct namespaces already in use:
  - `fitted_params:<catalyst_type>` — the estimator/sizing knobs, seeded by `seed_fitted_params`
    (`kb.py:272-328`) and read by `load_params` (`kb.py:396-405`). **Do not collide with this
    namespace** — it's the model-fit seam Phase 9 refits.
  - Free-form scenario playbooks (e.g. `"pdufa:crl_precedent"`) for the desk's `query_playbooks`
    tool (`tools.py:63-70`). This is where the warm-start generalizations go: "PDUFA with prior CRL +
    CMC observation history → X% CRL base rate, watch for Y."
- `strategy` is a free dict; `scenario` a human string. `confidence` ∈ [0,1] (`kb.py:258-259`).

## 3. EMBEDDER — the decision is already made and shipped

**Recommendation: keep `BAAI/bge-large-en-v1.5` (local, 1024-dim, fastembed/ONNX). Do NOT add an API
embedder.** This is not an open question — it's already in code and the deps are installed.

- **Why 1024?** `bge-large-en-v1.5` is a 1024-dim model. Migration 004 widened `kb_vec` to
  `float[1024]` specifically for it (`004_kb_vec_1024.sql:1-2`). The dim is coupled: model ↔ DDL ↔
  `EMBED_DIM` (`kb.py:27`). Swapping models means a new migration (drop/recreate vec0). So 1024 is
  the model, not a free parameter.
- **Local vs API — frugality verdict:** local wins decisively. `local_embed` (`kb.py:439-446`) runs
  ONNX on CPU, **no network, no rate limit, no per-call cost, private** (module docstring
  `kb.py:1-6`). The KB backfill embeds ~468 catalysts once, plus one embed per live analog_query
  (context string). An API embedder would (a) violate the frugality ladder for a datum trivially
  computable locally, (b) leak our thesis text off-box, (c) rate-limit the backfill. **No API.**
- **Loading is lazy + cached:** `_local_model()` imports `fastembed` and loads the model only on first
  embed, cached process-wide (`kb.py:431-436`). Tests never trigger it.
- **`default_embedder()` selection** (`kb.py:449-462`): `CT_EMBEDDER=hash` env → offline hash
  embedder (`kb.py:458-459`); else fastembed if importable (`kb.py:460-461`); else hash fallback.
  The desk uses `kb.default_embedder()` (`tools.py:59`); builder is passed an `embed` callable
  (`builder.py:113`). **Populate must use the SAME embedder as retrieval** — embed the backfill with
  `local_embed`, not `hash_embed`, or KNN is garbage. Set `CT_EMBEDDER` consistently (leave unset =
  fastembed) for both populate and serving.
- **The hash embedder** (`kb.py:408-421`) is plumbing-only, offline, deterministic, L2-normalized —
  keeps the whole KB testable with zero ML deps (`kb.py:5-6, 424-425`). Not semantic; never for prod
  retrieval.

**vec0 extension loading (confirmed working):** `db.connect()` does
`conn.enable_load_extension(True)` → `sqlite_vec.load(conn)` → `enable_load_extension(False)`
(`db.py:18-20`). The macOS caveat in CLAUDE.md (system Python often disables `enable_load_extension`)
is **already handled** — the repo uses the `.venv` Python 3.14 build (`sqlite_vec 0.1.9` installed)
which supports it, and `sqlite_vec` ships the loadable extension binary. No pysqlite3 needed. Cosine
distance is baked into the DDL (`004_kb_vec_1024.sql:6`), and `local_embed`/`hash_embed` return
L2-normalized vectors so cosine ranking is correct.

## 4. RETRIEVAL CONTRACT — what a model actually receives

### 4.1 The retrieval-context STRING (what we embed per query)

Today (`builder.py:62-63`): `_analog_context(verdict, target, ctype)` →
`f"{ctype} catalyst for {target}: {verdict.thesis}"`. The `verdict.thesis` is the desk's free-text
thesis — so analogs match on **mechanism/indication/setup described in prose**, which is exactly why a
semantic embedder matters.

**For the warm playbook, align the POPULATE `retrieval_text` (§2.1a) with the QUERY context shape.**
Both should describe the same axes so vectors land near each other: `{type} for {ticker}
{drug}/{modality} in {indication}; {key setup — endpoint status, precedent, CRL/AdCom history,
funding}`. The query side already has type+ticker+thesis; the populate side should mirror it
(mechanism, indication, modality, the driver tells). Matching the phrasing is what makes the KNN
retrieve on mechanism rather than surface tokens.

### 4.2 The `filters` dict + `k`

- `_structural_filter` (`kb.py:142-153`) is a hard pre-filter: a catalyst must match **every**
  `json_extract(attrs_json,'$.<key>') = <val>` before it can be semantically ranked
  (`kb.py:150-152`, `kb.py:179-181`, `kb.py:187`). Empty filters → all catalysts are candidates.
- Today builder passes `filters={"type": ctype}` (`builder.py:113`), k=5. The desk tool accepts an
  arbitrary `filters` dict from the agent (`tools.py:57-59`).
- **Recommendation:** default filter on `type` always; make `indication` an OPTIONAL conditioning key
  the desk can add for tight cohorts, but be careful — over-filtering on a 468-catalyst KB starves the
  KNN. `catalyst_move_estimate` needs `min_analogs` (default 5, `kb.py:355`) or it cold-starts
  (`events.py` `cold_start` flag). So: filter on `type` (partitions ~pdufa/readout/adcom), let
  semantic rank handle indication/mechanism similarity. Only add `indication` to filters when the type
  cohort is large enough to still yield ≥ `min_analogs`.
- **k:** over-fetch is built in — `analog_query` fetches `k*4` from vec0 then intersects with the
  structural candidate set and truncates to k (`kb.py:183-187`). Keep k=5 (matches estimator
  `min_analogs`); the `*4` over-fetch (k=20 rows) covers the structural intersection loss.

### 4.3 The formatted block injected into the desk prompt

The desk tools return analog results as **structured JSON to the agent** (the "updated context"), not
a pre-rendered string:
- `tools.py:59-61`: `_analog_query` returns `{"results": rows, "evidence_ref": ref}` where each row is
  the `_with_outcome` dict: `{node_id, distance, catalyst: {attrs}, outcome: {attrs}}`
  (`kb.py:164-169`). So the model literally receives, per analog: the full driver attrs +
  what_to_watch + the realized label + signed move + confidence. **This IS the "updated context"
  block** — the drivers explain *why*, `what_to_watch` is the pre-catalyst tell, the outcome+move is
  the base rate.
- Every analog carries an `evidence_ref` (`tools.py:60`) so the desk's cite-or-drop discipline holds
  (agents "NEVER compute/estimate/recall a figure" — must cite the tool ref, `company_scan.py:375`,
  `analysts.py:76`). The verifier checks analog refs (`verifier.py:144`).
- `query_playbooks` returns the generalizations similarly (`tools.py:66-68`), confidence-desc
  (`kb.py:337`).

### 4.4 Composition with the football-field estimator + fitted-params

The flow inside `builder.build` (`builder.py:109-121`):
1. `params = kb.load_params(conn, ctype)` (`builder.py:109`) — pulls the highest-confidence
   `fitted_params:<type>` playbook or the labeled `BOOTSTRAP_DEFAULT` (`kb.py:354-405`).
2. `analogs = kb.analog_query(...)` (`builder.py:113`) — retrieves the warm-start analogs.
3. `up_moves, down_moves = _split_moves(analogs)` (`builder.py:118`) — signed `outcome.move` split.
4. `catalyst_move_estimate(p_positive, up_moves, down_moves, params)` (`builder.py:120`, sig
   `events.py:51-57`) — the two-state up/down median mixture; magnitudes are the median of each
   branch, blended with an optional implied-move prior per `params["estimator"]["implied_blend"]`.
- The **football-field aggregator** (`quant/field.py:59` `expected_move_field`) is the SEPARATE
  multi-method convergence estimator: it stacks per-method magnitudes (analog median, implied move,
  base rate, rNPV, analyst PT) and takes the confidence-weighted trimmed median. Analog retrieval is
  **one method feeding the field** — the `weights` in `BOOTSTRAP_DEFAULT["field"]["weights"]`
  (`kb.py:386-390`) already distinguish `analog_cold` (0.5) vs `analog_warm` (1.0): **a warm playbook
  with real analogs promotes the analog method's weight in the field from 0.5→1.0.** That is the
  entire point of Phase 07.5 for the estimator: it moves the analog leg from cold to warm.

So: playbook populate → `analog_query` warm → `catalyst_move_estimate` gets real up/down branches →
enters `expected_move_field` at `analog_warm` weight → convergence point estimate. Fitted-params
playbooks tune the knobs at every step; scenario playbooks give the desk qualitative context.

## 5. NO-LOOK-AHEAD AT APPLICATION — the mechanism

### 5.1 The problem, precisely

The KB is built with full hindsight (allowed — CONTEXT §3, MEMORY warm-start note). Every node's
`created_at` (`kb.py:115`) = the backfill run time (e.g. 2026-08). At **application** time (backtest
cutoff W, or live), retrieval must only surface analogs whose **real-world outcome was knowable by the
decision date** — not by when we happened to build the KB.

**`analog_query` today has NO time filter at all.** `_structural_filter` (`kb.py:142-153`) filters
only on attr equality; `analog_query` (`kb.py:172-188`) does structural-filter → KNN → outcome-attach,
with no date parameter and no caller passing one (`builder.py:113`, `tools.py:59`). **A hindsight KB
queried through the current code leaks future analogs into a backtest.** This is a real gap.

### 5.2 Why the existing `serving.py` gate does NOT solve it

`serving.py` has a `kb_nodes` accessor gated on `created_at <= cutoff` (`serving.py:214-228`, registry
`serving.py:68`: `kb_node` knowable_expr=`created_at`). For a *live-written* KB that stamp is honest.
But for a **hindsight-built** playbook it is exactly wrong:
- Backtest at cutoff 2025-06: every analog has `created_at`=2026-08 > cutoff → the gate returns
  **NOTHING** (the whole warm playbook vanishes from every backtest).
- Live (cutoff=now): the gate returns **everything**, including any analog whose real outcome
  post-dates the decision.

Also, `analog_query` does not go through the `serving.Databook` at all — it's called directly on
`conn` (`builder.py:113`, `tools.py:59`), bypassing `kb_nodes`. So the serving gate never even runs on
the retrieval path.

The correct knowable stamp for an analog is **when its outcome became knowable in the real world** =
`catalyst_move.knowable_asof` (the T+2 close date, `010_catalyst_move.sql:15`), NOT `kb_node.created_at`.

### 5.3 The minimal fix (one attr at populate + one clause at query)

**Populate side (already specified §2.1a):** stamp each catalyst node with
`attrs["knowable_asof"] = <catalyst_move.knowable_asof>` — the ISO date the realized outcome became
knowable. It's a top-level attr so `json_extract` can filter on it.

**Query side — add an `as_of` param to `analog_query`** and one clause to the structural filter. This
is a ~3-line change, no new table, no schema migration:

```python
# kb.py analog_query(conn, embed, context, filters, k=5, as_of=None)
def _structural_filter(conn, filters, as_of=None):   # kb.py:142
    sql = "SELECT id FROM kb_node WHERE kind='catalyst'"
    params = []
    for key, val in filters.items():                 # unchanged (kb.py:150-152)
        sql += f" AND json_extract(attrs_json,'$.{key}')=?"; params.append(val)
    if as_of is not None:                            # NEW — no-look-ahead gate
        sql += " AND json_extract(attrs_json,'$.knowable_asof') <= ?"; params.append(as_of)
    return {r["id"] for r in conn.execute(sql, params).fetchall()}
```

Then thread `as_of` from the caller: `builder.build` already knows the decision cutoff (the weekly
sleeve runs at `cutoff=W` in backtest / `now` live — `weekly.py:96-98`, `serving.asof(conn, cutoff)`
`serving.py:81-83`). Pass that cutoff as `as_of` into `analog_query` (`builder.py:113`) and expose it
on the desk tool (`tools.py:57`). Default `as_of=None` = no gate = today's behavior (backward
compatible; tests unchanged).

**Why the attr, not a join:** the alternative is joining `kb_node.ref_id` → `catalyst_move.knowable_asof`
at query time. That works and reuses the existing stamp (single source of truth), but it's a heavier
SQL join inside the hot filter. Copying `knowable_asof` onto the catalyst node attr at populate time is
the ponytail move — it's a denormalized point-in-time stamp, populate is the one place it's written,
and the filter stays a pure `json_extract` like every other key. Ceiling: if `catalyst_move` is ever
recomputed with a different window, re-run populate (already required for idempotency). Document that
coupling in the populate script.

**Edge case — the outcome move itself must be knowable:** since the analog's `outcome.move` is the T+2
move and `knowable_asof` is the T+2 date, gating the catalyst on `knowable_asof <= as_of` guarantees
the attached outcome (via `RESULTED_IN`, `kb.py:156-169`) was also knowable. One gate covers both the
analog's existence and its realized move. No separate outcome-node gate needed.

### 5.4 Test the gate (money/correctness path — ponytail requires one check)

One `test_*.py`: populate two catalyst nodes, `knowable_asof` = 2024-01 and 2025-06; assert
`analog_query(..., as_of="2024-06")` returns only the first (and its outcome), and `as_of=None`
returns both. That's the smallest thing that fails if the no-look-ahead clause breaks. This is the
single hardest correctness guarantee in the phase — it's what makes the year backtest honest despite a
hindsight-built KB (MEMORY warm-start: "no-look-ahead is an APPLICATION-time rule").
