# Phase 07.5 — The Warm Playbook (project core)

**What it is (CEO framing):** the playbook is THE MEAT of the project — the updated, structured CONTEXT the models reason with. For every past catalyst in our PEER UNIVERSE (73 names), it captures what happened, WHY it happened (the outcome drivers), and what a future analyst should watch for. Built with FULL HINDSIGHT (allowed at construction); the no-look-ahead rule applies only at APPLICATION time (retrieval must filter to what was knowable as-of the decision).

**Grounding (already exists — do NOT rebuild):**
- `kb.py` scaffold: `KBNode`(kinds: catalyst/company/playbook/prediction/hedge_peer/evidence_source), `kb_edge`(rels incl. CITES, RESULTED_IN), `insert_claim` (node+evidence+CITES+optional vector), `analog_query(embed, context, filters, k)` (vector similarity over `kb_vec` + structural filter + attaches outcome via RESULTED_IN), `insert_playbook(scenario_type, scenario, strategy, confidence, evidence)`, `seed_fitted_params`, `insert_hedge_peer`/`hedge_peers`. KB is EMPTY (0 nodes).
- `kb_vec` = sqlite-vec float[1024] cosine (needs the vec0 extension loaded + a real embedder — currently stubbed).
- Raw material: 1049 catalysts, 468 SIGNED moves, 2011 catalyst_source provenance rows, 1920 8-K exhibits in `data/raw/edgar_8k/`, 73-name universe + `data/universe_profiles.json` (per-company lead asset/indication/modality).
- Football-field estimator (07.7 Wave 1) exists to be fed by playbook context.

## The 5 design questions to define (via research) BEFORE building

1. **WHAT GOES IN IT (content + schema).** The per-catalyst record + the per-scenario generalization. Needs a real biotech CATALYST-OUTCOME DRIVER TAXONOMY: for PDUFA (approve vs CRL) and trial-readout (hit/miss/mixed) and AdCom, what are the causal factors a playbook must record (endpoint design, prior Ph2 effect size, mechanism validation/precedent, FDA/AdCom history, CRL history, safety signal, financing/runway, competitive position, label/commercial) + the pre-catalyst "what-to-watch" tells. Plus: outcome label enum, realized signed move, confidence, citations.
2. **HOW IT'S BUILT.** The construction pipeline: from our 8-K exhibits + press releases + CT.gov + signed moves + profiles, attribute each past catalyst's outcome + drivers into KB nodes/edges. Automated LLM extraction vs curated? Which sources per catalyst type? Idempotent, cited.
3. **HOW MODELS PULL FROM IT (retrieval).** `analog_query` (vector) — which embedder (local CPU vs API), what the retrieval context string is, type/indication-conditioned filters, k, and how retrieved analogs+outcomes+drivers FORMAT into the model prompt (the "updated context" block). How it composes with the football-field estimator + fitted-params playbooks.
4. **HOW WE IDENTIFY WHAT HAPPENED (outcome attribution).** The labeling step: per past catalyst, derive the outcome (approve/CRL/hit/miss/beat/miss) + causal drivers from the announcement 8-K/press release text + the signed price move + news. Confidence + citation per label. This is the hardest correctness piece.
5. **SCOPE.** Peer universe (73 names) historical catalysts only. Quantify: how many peer catalysts have (a) a computable signed move AND (b) source text to attribute from.

## Constraints (locked)
- Reuse the `kb.py` scaffold; no duplicate KB. Populate, don't rebuild.
- Cite-or-drop: every driver/outcome cites its source (insert_claim invariant).
- No-look-ahead at APPLICATION only (hindsight construction OK); retrieval filters to knowable-as-of.
- Frugality: build from cached 8-K/CTgov lake + stored data first; external calls only where a datum is genuinely unavailable (free-first).
- Peer universe scope only.

## LOCKED DECISIONS (CEO sign-off 2026-08-18) — fold into the build

**Node = written CASE, not enum rows (research D+E).** Two layers per catalyst:
- STRUCTURED ENVELOPE (deterministic, filters retrieval, read-only facts): ticker, type, indication, asset, `knowable_asof` (leak gate), outcome_label, `signed_move`, confidence, move_consistency_flag, drivers{~18 taxonomy fields}.
- NARRATIVE BODY (the reasoning substrate — THIS is embedded into kb_vec, not a one-liner):
  - before: `thesis`, `causal_setup`, `reference_class` (named precedent group + base rate), `variant_why`, `what_to_watch`, `what_would_change_our_mind`
  - after (post-mortem): `what_happened`, `why_narrative` (causal story in industry/company/regulatory context — the meat), `surprise_vs_prior`, `which_disconfirmer_fired`, `lesson_rule` (graduates to a playbook generalization node), `second_order`
- Embedded text = composed narrative card (thesis + causal_setup + reference_class + why_narrative). Every claim CITES its source (cite-or-drop). Bi-temporal: invalidate-don't-overwrite.

**Sign-off calls:** extractor = SONNET (~$7 one-time); include the 118 peer EARNINGS as a distinct context tier (kept separate from binary-catalyst analogs); FULL ~18-field driver taxonomy.

**Population (research B):** Sonnet, 1 call/catalyst, CIK-filter FIRST (drop 41% cross-company exhibits), bundle = own-company 8-K/PR text + CT.gov status + signed move → structured JSON → insert_claim (idempotent on catalyst_id+hash). PDUFA: move is primary outcome anchor, text corroborates; readout: text primary, move corroborates; consistency flag on disagreement. Scope: 218 binary core + 118 earnings; skip/flag month-precision (move=null), no-exhibit, naked.

**Retrieval (research C):** local bge-large embedder (shipped); analog_query filters type always + indication if cohort≥5 + `knowable_asof <= decision cutoff` (NEW leak clause + test); promotes football-field analog leg 0.5→1.0. Generalizations = insert_playbook nodes from recurring lesson_rules.
