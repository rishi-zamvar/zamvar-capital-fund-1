# 07.5 RESEARCH-B — Outcome Attribution & Raw-Material Inventory

**Scope:** CONTEXT design-question **#4 (how we identify what happened)** + **#5 (scope quantification)**. Complements RESEARCH-A (taxonomy/schema). Internal-only: everything below was read from `catalyst.db`, `data/raw/`, and `src/` — no web calls.

**Headline:** We can retrieve, for essentially every peer catalyst that has a signed move, **both** (a) the announcement text and (b) the signed price move, via a **100%-deterministic** join. But two data-quality realities reshape the pipeline: (1) **41% of peer PDUFA/readout catalysts have cross-company contaminated exhibit links** (must CIK-filter), and (2) **the lake's 8-K exhibits skew to date-establishing filings (FDA-acceptance PRs), not decision-day outcome 8-Ks** — so for PDUFAs the **signed move is the primary outcome signal and text is corroboration**, inverting the naive "text-first" framing.

So direction (approve↑ / CRL↓) and magnitude are both directly readable.

### 1.2 The 8-K exhibit lake

- **Layout:** `data/raw/edgar_8k/<YYYY>/<MM>/` — flat, **1918 `.txt` files** (1217 distinct URL stems), all currently under `2026/08` (the harvest month), *not* the filing month. Written by `providers/_http.py::_write_snapshot` (`_http.py:79`) which archives the **raw HTML** of any successful `get_text("edgar_8k", url, ua="sec")` (callers: `providers/pdufa_edgar.py:368`, `universe/discover.py:334`).
- **File naming = the join key.** `_safe_name(key)` (`_http.py:69`) → `<last-URL-path-segment, ≤40 sanitized chars>_<sha1(f"{url}(){None}")[:8]>`, then `_write_snapshot` appends `_<UTC timestamp>.txt` (`_http.py:85`). For a plain GET the key's `params=()` and `json_body=None`, so the sha1 is over the literal string `url + "()" + "None"`.
- **Verified linkage: 100%.** For all **942** `catalyst_source` rows whose `source_url` is a `sec.gov/Archives` link, recomputing `_safe_name(source_url)` and stripping the trailing timestamp matched a lake file **942/942, 0 misses**. So the canonical retrieval join is:

  ```
  catalyst.id → catalyst_source.source_url (LIKE '%sec.gov/Archives%')
             → _safe_name(url) → data/raw/edgar_8k/**/<stem>_<ts>.txt → read_text()
  ```
  (`providers/_http.py::load_snapshot`, `_http.py:101`, re-parses offline — no network.)

- **CT.gov side:** `catalyst_source` rows with `source_url LIKE '%clinicaltrials.gov/study/%'` (604 `ctgov` + 42 `ClinicalTrials.gov` by `source_name`) give the NCT id → trial status/phase. A separate `data/raw/ctgov_discover/` lake exists for CT.gov JSON. `data/ctgov_sponsor_review.csv` (343 KB) is the sponsor-attribution audit.

## 3. Attribution pipeline design

### 3.1 Shape: LLM extraction agent, one call per catalyst

Yes — an **LLM extractor per catalyst** is the right tool (deterministic parsing of free-form FDA/PR prose into approve/CRL/hit/miss + drivers is exactly an LLM job, and RESEARCH-A already fixed the output schema). Per catalyst the agent receives a **CIK-filtered, event-proximate context bundle** and emits structured JSON:

```
INPUT  (per catalyst_id):
  - catalyst row: ticker, type, event_date, date_precision
  - company profile: lead_asset, indication, modality  (universe_profiles.json)
  - exhibit text: CIK-filtered, closest-reported_date-to-event_date, tag-stripped (§3.2)
  - ctgov status/phase (if a study link exists)
  - signed realized_move + window + knowable_asof   (the cross-check anchor)
OUTPUT (RESEARCH-A schema):
  { outcome_label, drivers:[{factor, evidence_quote, source_url}],
    what_to_watch, confidence, move_consistency_flag,
    citations:[{url, quote, snippet_hash}] }
```

Then persist via `kb.insert_claim` (`kb.py:103`): a `catalyst` node, an `outcome` node, a `RESULTED_IN` edge (`kb.py:156` reads it back), and a `CITES` edge per driver quote. The invariant (`kb.py:111`) enforces cite-or-drop for free.

### 3.2 CIK-filter FIRST (the biggest correctness fix)

**89 of the 218 peer pdufa+readout catalysts (41%) link exhibits from ≥2 distinct CIKs** — cross-company contamination (LPCN↔Acumen, ALDX↔Zenas, ABEO↔Cognition all observed). Only 74 have a clean single-CIK set; 55 have no edgar exhibit at all. So before any LLM sees text:

1. Extract CIK from each URL (`/data/<CIK>/`).
2. Keep only exhibits whose CIK maps to the catalyst's ticker (map via `edgar.Company(ticker).cik` — one cached edgartools lookup per ticker, as `providers/edgar.py:67` already does — or a one-time ticker→CIK table).
3. Among survivors, pick the exhibit whose `catalyst_source.reported_date` is **closest to `event_date`**.
4. **Cite-or-drop:** if nothing survives the CIK filter, do not feed a wrong-company exhibit — fall through to §4 (ctgov + move, or targeted fetch).

### 3.3 Signed move is the outcome anchor for PDUFAs (not just corroboration)

The lake exhibits were harvested by the **PDUFA-date-discovery** crawler (`pdufa_edgar.py`), so for PDUFAs they are overwhelmingly **"FDA Accepts / Grants Priority Review / PDUFA target action date is…"** filings — the event that **established the date**, filed months *before* the decision. The **approval/CRL decision 8-K is usually absent from the lake.** Confirmed across the peer PDUFA sample (KRYS, LPCN, ABEO, INSM, CAPR all show acceptance-PR text).

Consequence: for `pdufa`, **derive the outcome primarily from the signed move** (large positive ⇒ approve; large negative ⇒ CRL/delay), use the acceptance PR as *context* (indication, priority-review, prior-CRL mentions → drivers), and **optionally fetch the decision 8-K** (one targeted, free EDGAR full-text-search for that CIK within ±5 trading days of `event_date`) only when a clean decision text is needed for the citation. For `trial_readout`, the linked PR is more often the outcome itself, so text-first is fine there — but the move still cross-checks.

### 3.4 Cross-check (the "text says approved but stock fell" flag)

Every record carries a `move_consistency_flag`: compare the text-derived label's expected sign against `realized_move`. approve/hit ⇒ expect `> 0`; CRL/miss ⇒ expect `< 0`. On disagreement (or |move| tiny for a "major" label), set the flag and **lower confidence** — do not silently trust either side. These flagged rows are the human-review queue. Month-precision rows (no move) are auto-flagged `move=null, corroboration=unavailable`.

### 3.5 Idempotent + cited

- **Idempotent:** key the work on `catalyst_id`; skip if an `outcome` node with a `RESULTED_IN` from that catalyst already exists. Re-run only when the source content hash changes (store a `content_sha` on the outcome node; the evidence dedup on `(url, snippet_hash)` at `kb.py:76` already prevents duplicate citations).
- **Cited:** `insert_claim` refuses an evidence-less claim (`kb.py:111`); every driver must quote a span from the CIK-matched exhibit or the ctgov record. No quote ⇒ drop the driver, don't invent one.

### 3.6 Volume + token cost

- **To process (core):** 218 peer pdufa+readout catalysts (+118 earnings if that pass is wanted).
- **Exhibit sizes** (232 distinct peer pdufa+readout exhibit files, tag-stripped): median ~14 k chars (~3.5 k tokens), mean ~22 k (~5.6 k), p90 ~40 k (~10 k). Total ~**1.3 M tokens** if every exhibit is read once.
- **LLM-per-catalyst budget:** ~1.6 M input (exhibits + ~1.5 k/catalyst prompt & move/ctgov context) + ~0.17 M output (~800-token JSON × 218). At **Haiku ≈ \$2**, at **Sonnet ≈ \$7** for the whole core corpus — trivial, one-time. Cache the shared taxonomy/system prompt across calls. Recommend Sonnet for the money-touching correctness; Haiku only if a cost ceiling appears.

## 4. Gaps — handled honestly, never fabricated

| Gap | Peer count | Honest handling |
|---|--:|---|
| **Month-precision readouts** (no move anchor) | 46 | Attribute outcome from text only; store `move=null`, `corroboration=unavailable`, lower confidence, auto-flag. |
| **No edgar exhibit** (pdufa+readout) | 55 | Use ctgov status + signed move; optionally one targeted free EDGAR FTS fetch. If still nothing → **skip** (no node), don't guess. |
| **Cross-company contaminated links** | 89 (41%) | CIK-filter (§3.2); if no own-company exhibit survives → treat as "no exhibit" (row above). |
| **PDUFA acceptance-PR ≠ decision** | most of 23 | Move-anchored outcome + PR-as-context; fetch decision 8-K only when a decision citation is required (§3.3). |
| **No AdCom / conference history** | 0 exist | Playbook simply has none; taxonomy fields stay unpopulated. State it, don't synthesize. |
| **Fully naked** (no move, no text) | 8 | Skip entirely. |
| **`universe_profiles.json` has 76 vs 73 snapshot** | — | Reconcile to the 73 `included` snapshot tickers at build; don't attribute the 3 extras. |

**Net attributable playbook:** ~**218 core catalysts** (pdufa+readout), of which ~**148** get full move+own-company-text corroboration (129 readout-with-move that pass CIK-filter + 19 pdufa-with-move), the rest attributed at reduced confidence with explicit flags. Earnings (118) optional, separate pass.
