# Phase 07.5 Plan 01: Warm-Playbook Record Contract Summary

Defines the warm-playbook record contract as a pure, DB-free, LLM-free pydantic v2 module
(`playbook/schema.py`) on the existing kb.py scaffold with ZERO migration: `CatalystRecord`
(structured envelope + ~18-field driver taxonomy + before/after narrative + SIGNED move), the
`compose_card` four-field narrative composer that becomes the kb_vec embed_text, and the
`to_catalyst_attrs`/`to_outcome_attrs` node-attr mappers that enforce the two money-path invariants.

## What Was Built

- **`CatalystRecord`** — full case contract: envelope (ticker, catalyst_type, indication, modality,
  event_date, `knowable_asof`, outcome_label, `signed_move`, move_window, confidence,
  move_consistency_flag), `drivers: list[DriverClaim]`, `narrative_before`, `narrative_after`,
  non-empty `citations`. `model_validator(mode="after")` enforces confidence∈[0,1], non-empty
  citations, and computes `move_consistency_flag`.
- **`DriverClaim`** — `{factor, value, evidence_quote, source_url}` all required (field-level
  cite-or-drop; a quote/source-less driver is dropped by the Plan-03 extractor, never constructed).
- **`Citation`**, **`NarrativeBefore`** (thesis/causal_setup/reference_class/variant_why/what_to_watch/
  what_would_change_our_mind), **`NarrativeAfter`** (what_happened/why_narrative/surprise_vs_prior/
  which_disconfirmer_fired/lesson_rule/process_grade/second_order?). All `extra="forbid"`.
- **`compose_card(record)`** — joins exactly thesis + causal_setup + reference_class + why_narrative
  (leads with thesis to align with the query-side context `"<type> catalyst for <target>: <thesis>"`,
  builder.py:62). Excludes variant_why/what_to_watch.
- **`to_catalyst_attrs`** — top-level filter keys (type/ticker/indication/modality/knowable_asof/
  event_date), nested drivers (flattened `{factor: value}`), nested narrative_before/after,
  `retrieval_text = compose_card(record)`.
- **`to_outcome_attrs`** — `{label, move: signed_move, move_window, confidence, read_only: True}`.
- **`compute_move_consistency`** — positive labels (approve/hit/beat/…) expect >0, negative
  (CRL/miss/reject/…) expect <0; disagreement → True; None move → False; unknown label → False.

## Money-Path Invariants Enforced

- Outcome key is literally `"move"` and SIGNED (`==`, not abs) — `_split_moves` (builder.py:69) split-by-sign contract.
- `knowable_asof` and all structural-filter keys are TOP-LEVEL attrs (kb._structural_filter json_extract reads top-level only).
- `compose_card` is the four narrative fields only — the string embedded into kb_vec.
