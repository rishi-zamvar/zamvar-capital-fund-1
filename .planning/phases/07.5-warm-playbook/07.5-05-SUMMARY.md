# Phase 07.5 Plan 05: Warm-Playbook Generalization Summary

**`generalize_playbooks(conn)` graduates recurring per-catalyst `lesson_rule`s into cited, confidence-surfaced free-form `{type}:{slug}` scenario playbook nodes — carrying base rate, median signed move, member ids and the unioned watch-list — that the desk's `query_playbooks` tool consumes, without ever touching the reserved `fitted_params:<type>` namespace; wired as the closing step of the one-time build script, plus the Plan-04-flagged embedder-consistency guard on the query path.**

## Accomplishments

- **`generalize_playbooks(conn, min_support=2)`** — `_harvest` groups the populated catalyst corpus by `(type, reference_class)` (newest node per `ref_id` wins, so a content re-write isn't double-counted), collecting each member's `lesson_rule`, realized outcome (label + SIGNED move), watch-list, and CITES evidence. Each group with `>= min_support` members becomes ONE `insert_playbook` node: scenario = the most common lesson_rule; strategy = `{base_rate, median_move, n, member_ids, what_to_watch, reference_class}`; confidence = label-agreement × support; evidence = the deduped union of members' `EvidenceSource`. Returns the count written.
- **Namespace safety (the money guard)** — `scenario_type = f"{type}:{_slug(reference_class)}"` with a runtime `assert not scenario_type.startswith("fitted_params:")`. A test seeds a `fitted_params:pdufa` node, runs generalize, and asserts `load_params(conn,'pdufa')` is byte-identical afterward — the reserved estimator-param seam is provably never written or shadowed.
- **Idempotent + cite-or-drop** — a second call writes 0 (existing `scenario_type` skipped, not duplicated); a group with no cited members can't graduate; every write routes through `insert_playbook` → `insert_claim` so the CITES invariant holds atomically. No raw `kb_node` SQL, no `seed_fitted_params`.
- **Build-script wire** — `build_playbooks.py --run` now calls `generalize_playbooks` after the populate loop (same one-time pass) and prints `n` scenarios by type; `--dry-run` stays pure-SQL offline (verified against the live 468-catalyst `catalyst.db`: 268 core + 200 earnings, no generalize, no spend).
- **Plan-04 dependency honored** — `desk/builder.build` and the `desk/tools` `analog_query` handler now call `assert_embedder_consistency` immediately before `kb.analog_query`, so a query embedder that doesn't match the populate embedder fails loud rather than returning garbage KNN. Covered by a new tool-level test.

## Deviations from Plan

### Design choices within plan scope

**1. [Rule 2 - Correctness] Embedder guard wired at BOTH query call sites (Plan-04 flagged dependency)**
- **Found during:** Task 3 (the prompt/Plan-04 SUMMARY flagged that the retrieval path must call `assert_embedder_consistency` before `analog_query`).
- **Fix:** Added the guard to the two live query paths that pass an embedder — `desk/builder.py:build` (its own `embed`) and `desk/tools.py:_analog_query` (`kb.default_embedder()`). The guard function already lived in `playbook.store` (Plan 04); this plan wires the callers + a regression test. Not put inside `kb.analog_query` itself: `kb` is a lower layer than `playbook.store` (store imports kb), so calling the store guard from kb would invert the dependency — the two call sites ARE the query path.
- **Files modified:** `src/catalyst_trader/desk/builder.py`, `src/catalyst_trader/desk/tools.py`, `tests/test_desk_tools.py`
- **Commit:** 3280165

**2. [Rule 2 - Correctness] Harvest uses catalyst-node narrative, not outcome-node narrative**
- The plan's interface comment said "outcome nodes carry `narrative_after.lesson_rule`". In the actual Plan-01/04 schema, `to_outcome_attrs` emits only `{label, move, move_window, confidence, read_only}` — the full `narrative_before`/`narrative_after` (incl. `reference_class` and `lesson_rule`) lives on the CATALYST node. `_harvest` reads `reference_class`/`lesson_rule`/`what_to_watch` from the catalyst node and `label`/`move` from the RESULTED_IN outcome. No corner cut — the grouping key and lesson come from where the data actually is.
