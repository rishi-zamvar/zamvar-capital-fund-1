# Phase 07.7 — Football-Field Valuation Plugin Suite

**Goal:** Replicate how hedge funds build a valuation/expected-move **football field** — compute the move/value *every principled way*, assemble the range, then pick the convergence value the signals agree on — and expose each method as a **canonical, reusable plugin** our agents call. Wire it into the existing desk workflow so the Trade Builder produces a football-field magnitude and the MD reconciliation loop can flag a Trade-Builder-vs-DD number discrepancy.

**Depends on:** Phase 5 (trade builder `desk/builder.py`, `quant/` tool library), Phase 6 (diligence firewall), Phase 6.7 (MD reconciliation loop — already wired), Phase 6.5 (`quant/weekly.py`).

## Governing constraints (user-locked — do NOT violate)

1. **No duplication. Reuse first.** Before writing ANY method, check the existing `quant/` library. If a canonical version exists, **parameterize it** and pass company values in — do NOT fork a second function that does the same thing with different params. Multiple near-identical functions confuse the calling agent; that is the exact failure we are preventing.
2. **One canonical function per analysis.** Each principle/basic analysis every fund has = exactly one generic plugin. Generic math only; no company-specific constants baked in.
3. **Company-specific params live in playbooks/assumptions, injected at call time** — never hardcoded into the analysis function. (Discount rate, PoS, comps set, peak sales, etc. come from the per-company playbook.)
4. **Each analysis lives in its proper module.** Valuation methods → `quant/valuation.py`; options-implied → `quant/options.py`; base-rate/analog → `quant/weekly.py`/`quant/events.py`; the aggregator → its own home. Don't stuff unrelated analysis into an existing function.
5. **Every plugin returns the existing `ToolResult` contract** (`quant/result.py`: tool, tool_version, inputs, value, detail) — versioned, immutable, reproducible.
6. **New analysis → new plugin, stored for reuse.** When an agent needs an analysis we don't have, it builds it as a canonical plugin (with tests) and it becomes part of the library for future calls — not a one-off inline computation.
