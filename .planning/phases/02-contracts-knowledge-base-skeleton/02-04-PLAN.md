<objective>
Build the three read/query capabilities on top of the provenance write-path: analog retrieval (KB-03), the hedge-relationship sub-store (KB-04), and the playbook store (KB-05). All three are thin: analog is a structural SQL filter then a KNN rank over `kb_vec` then a traverse to the `Outcome` node; hedge peers and playbooks are just `HEDGE_PEER` edges and `playbook` nodes written through `insert_claim` so they inherit the mandatory-citation invariant for free.

Purpose: closes the remaining phase success criteria — downstream agents (analysts pull base rates, trade builder pulls hedge peers, researchers pull playbooks) query these. The two-tier analog design deliberately routes around sqlite-vec's alpha metadata-filter API (SQL filter + python-set intersect), so it is robust to that API's churn.
Output: `kb.py` gains `analog_query`, `insert_hedge_peer`/`hedge_peers`, `insert_playbook`/`query_playbooks`, each with its own test suite.
</objective>

```python
def analog_query(conn, embed, context: str, filters: dict, k: int = 5):
    cand = _structural_filter(conn, filters)   # set[int]: kb_node.id where kind='catalyst' AND attrs match filters
    q = serialize_float32(embed(context))
    rows = conn.execute("SELECT node_id, distance FROM kb_vec WHERE embedding MATCH ? AND k = ? ORDER BY distance",
                        (q, k*4)).fetchall()     # NB: env is SQLite 3.53 -> may use `ORDER BY distance LIMIT ?` instead of `AND k=?`; use whichever the smoke test confirms works
    ranked = [r for r in rows if r["node_id"] in cand][:k]
    return [_with_outcome(conn, r["node_id"], r["distance"]) for r in ranked]  # traverse RESULTED_IN -> Outcome
```
