<domain>
## Phase Boundary

One database (`catalyst.db`), served through a MANDATORY gateway bound to a **cutoff date**: every read returns only what was KNOWABLE strictly before that cutoff. Live uses `cutoff = now`; a walk-forward at week W uses `cutoff = W`. This closes the **data-layer half** of look-ahead leakage — the complement to the strategy-layer guards already shipped (`bars_asof`/`universe_as_of` valid-time filters + events.py's `last_verified_at` post-filter).

Ends with: (1) a bitemporal schema (transaction-time stamps on every served table), (2) a single serving seam `serving.asof(conn, cutoff)` that is deny-by-default, (3) a per-table stamp audit encoded as a registry with the wrong/missing stamps fixed, (4) adversarial leak-property tests, and (5) the backtest + shared-quant + live-desk reads rewired through the gateway. It does NOT change any strategy math, sizing, or selection — behaviour-preserving on correct data, leak-denying on incorrect data.

**Requirement IDs (proposed — NOT yet written to REQUIREMENTS.md; operator reconciles):**
DBOOK-01 (bitemporal schema), DBOOK-02 (append-never-overwrite revision semantics), DBOOK-03 (mandatory serving gateway), DBOOK-04 (deny-by-default), DBOOK-05 (per-table stamp audit + registry + catalyst event_date-bug fix), DBOOK-06 (realistic ingestion lag), DBOOK-07 (leak-property / temporal non-interference tests), DBOOK-08 (wire money-path reads through the gateway).
</domain>

<grounding>
## Established practice this phase is grounded in

- **Point-in-time / bitemporal financial data.** S&P Capital IQ PIT and Compustat PIT: *append a new version per filing, never overwrite; a period's value comes from only the one applicable filing whose knowable-time precedes the as-of.* This phase mirrors that exactly for amended catalysts (a revised PDUFA date is a NEW version row; a replay before the amendment returns the OLD date).
- **Feature-store point-in-time-correct joins** (Tecton / Feast "PIT joins"): a feature value must be joined by *when it became available*, not by the event's own timestamp — the same valid-time-vs-transaction-time separation encoded here.
- **Availability-gate / temporal non-interference formalizations:** OpenPM (arXiv 2608.09988) and the non-interference framing (arXiv 2607.04958) — a backtest must be *provably* unable to condition on post-cutoff information. The leak-property tests (DBOOK-07) are the operational form of that non-interference property: an adversarial read of post-cutoff data through the gateway MUST be denied.

The classic bug these guard against: stamping a fact by **when it HAPPENED** (fiscal period-end, the scheduled PDUFA date, the bar's week close) instead of **when it was KNOWABLE** (the filing/announcement date). The two must be distinct columns, and the gateway must gate on the *knowable* one.
</grounding>

<decisions>
## LOCKED design decisions (operator-confirmed)

### A. Bitemporal — two timestamps, append-never-overwrite
- Every served fact carries BOTH **valid time** (when it happened: `event_date`, `week_end`, `as_of_date`) and **transaction/knowable time** (when WE recorded/learned it). Add a `recorded_at` transaction-time column wherever it is missing.
- **Append-never-overwrite on revisions:** a changed fact (e.g. an amended PDUFA date) becomes a NEW row with its own later transaction time; the old row is retained. An as-of query returns the LATEST version whose transaction-time `<= cutoff` — so a replay before the amendment returns the OLD date, after returns the NEW.
- A migration for the transaction-time columns is expected and sanctioned.

### B. Mandatory serving gateway, deny-by-default
- A single access seam: `serving.asof(conn, cutoff)` returns an as-of "databook" whose accessors inject the `knowable <= cutoff` transaction-time filter on every served table (in ADDITION to the existing valid-time `<= as_of` guard). ALL reads on the backtest + live paths go through it. A raw `store.*_asof` call on those paths is a reviewable bug.
- **Live = same gateway, `cutoff = now`.** This kills live-vs-backtest logic drift — the subtlest leak — because both paths execute identical read code.
- **Default-DENY:** a served table with no registered/correct knowable stamp (or a NULL stamp on a row) is BLOCKED (raise), never leaked with a green light.

### C. Per-table stamp audit (the deliverable)
Audit every served table for WHICH column is the correct transaction/knowable stamp; document it; fix or add where wrong/missing; apply a realistic ingestion lag where the idealized public date overstates what we'd actually have had. The audit is ENCODED as a `STAMP_REGISTRY` in `serving.py` (the code is the documentation) and reproduced in the table below.

### D. Leak-property tests (temporal non-interference)
Adversarial tests that ATTEMPT to read post-cutoff data through the gateway and ASSERT denial; a revised fact returns the as-of-then version (old date before amendment, new after); a table lacking a stamp is denied by default; derived/feature computations use only pre-cutoff rows (no whole-table stats leaking a future value).
</decisions>

Amendments currently OVERWRITE (`insert_catalyst` UPDATEs in place, store.py L88) — that destroys the old version, so a pre-amendment replay is impossible. **Fix:** add append-only version history + gate on the version's `recorded_at`. |

<gateway_design>
## Gateway design (`src/catalyst_trader/serving.py`)

- **`STAMP_REGISTRY: dict[str, StampSpec]`** — one entry per served table declaring `(valid_col, knowable_expr, data_class)`. This IS the encoded audit. A table absent from the registry → deny-by-default.
- **`asof(conn, cutoff, *, latency_cfg=None) -> Databook`** — returns an accessor object whose read methods wrap the existing `store.*_asof` / `universe_as_of` reads and ADD the `knowable <= effective_cutoff` filter, where `effective_cutoff = fill.effective_asof(data_class, cutoff, latency_cfg)` when a lag is configured (DBOOK-06 REUSES the shipped lag transform — no new lag mechanism). `cutoff = now` for live.
- **Bitemporal read for `catalyst`:** the accessor resolves each catalyst's event_date from the LATEST `catalyst_version` row with `recorded_at <= cutoff` (append-never-overwrite as-of), then applies the existing `status='verified'` + valid-time window. Live (`cutoff=now`) collapses to the current materialized row (fast path).
- **Deny-by-default enforcement:** any accessor for an unregistered table, or a served row whose knowable stamp is NULL, RAISES `LookAheadDenied` — never returns a partial/green result.
- **Blast-radius containment:** accessor method signatures MIRROR the existing store functions (`bars`, `card`, `scan_flags`, `catalysts`, `universe`) so wiring (Plan 05) is a mechanical seam swap, not a rewrite.
</gateway_design>

<risks_for_plan_check>
## Risks for the plan-checker to scrutinize
1. **`insert_catalyst` append-never-overwrite change (Plan 01)** touches a shipped money-path write. Blast radius: every catalyst reader assumes one row per `(ticker, external_ref)`. Mitigation chosen: keep the main `catalyst` row as the materialized LATEST (live-view cache; existing readers unaffected) and add a SEPARATE append-only `catalyst_version` history table that the gateway reads for historical cutoffs. Verify idempotency: an unchanged re-fetch must NOT append a version; only a changed `event_date` appends.
2. **price_bar/company_card DO NOT gate on `retrieved_at`** — the backfill trap. A plan that "helpfully" adds a `retrieved_at <= cutoff` filter would silently break the entire backtest (deny all backfilled history). The registry must gate on `week_end` (+ lag).
3. **Deny-by-default must fail LOUD** — an unregistered table or NULL stamp raises, never returns `[]` (an empty result masquerading as "no data" is a silent leak of the deny signal).
4. **Live path must use the SAME gateway** (`cutoff=now`) — a live code path that keeps calling raw `store.*_asof` reintroduces logic drift. Plan 05 must wire live too, not just the backtest.
5. **Behaviour preservation** — on correct data at a correct cutoff the gateway must return EXACTLY what the raw reads return today (the full 1183-test suite is the regression net; wiring is a seam swap, not a math change).
6. **Ingestion lag reuses `effective_asof`** (raises on unconfigured class) — confirm the gateway does not silently default to 0-lag for a data class, which would reopen look-ahead.
</risks_for_plan_check>
