# Phase 07.6 Plan 01: Bitemporal Schema Foundation Summary

Migration 011 adds the transaction-time stamps the audit found MISSING (`scan_flag.recorded_at`, `universe_snapshot.recorded_at`) and an append-only `catalyst_version` history table so amended catalyst dates are RETAINED as versions instead of overwritten; `insert_catalyst` now appends a version only on a changed `event_date` (idempotent on an unchanged re-fetch), and `catalyst_version_asof` resolves the event_date knowable at any cutoff.

## What was built

- **Migration 011** (`011_bitemporal.sql`): two `ADD COLUMN recorded_at` + `CREATE TABLE catalyst_version` (id, catalyst_id, event_date, event_date_end, recorded_at) + index + a non-destructive, idempotent guarded backfill.
- **store.catalyst_version_asof(conn, catalyst_id, cutoff)** → `{event_date, event_date_end, recorded_at}` of the latest version with `recorded_at <= cutoff`, else None. The replay primitive the gateway (Plan 02+) builds on.
- **store.insert_catalyst**: new insert writes version-1; an existing (ticker, external_ref) match appends a version ONLY when `(event_date, event_date_end)` changed; the materialized main row is always refreshed to the latest (live-view cache).
- **write_scan_flag / build_snapshot**: both now stamp `recorded_at = now_iso()`.
