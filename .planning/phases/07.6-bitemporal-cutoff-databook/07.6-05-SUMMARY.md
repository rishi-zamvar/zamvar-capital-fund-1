# Phase 07.6 Plan 05: Wire Money-Path Reads Through the Gateway Summary

The backtest read-path (`events.py`, `engine.py`), the shared deterministic sleeve (`quant/weekly.py`), and the live desk reads (`desk/weekly`, `desk/risk`, `desk/company_scan`, `pipeline`) now route through the mandatory serving gateway — backtest at `cutoff=W`, live at `cutoff=now` — so both paths execute IDENTICAL read code (decision B, live-vs-backtest logic drift eliminated). `events.py`'s ad-hoc `last_verified_at` post-filter is replaced by the gateway's bitemporal `book.catalysts()` resolve.

## What was wired

- **backtest/events.py**: universe/bars via a no-lag book; catalysts via `cat_book.catalysts()` (carries the catalyst-class ingestion lag). The manual `last_verified_at` post-filter is GONE.
- **backtest/engine.py**: `_fill_leg` bars via the gateway (entry cutoff=as_of, exit cutoff=exit_by); the sleeve runs through `qw.as_of_view(conn, as_of)`.
- **quant/weekly.py**: `as_of_view` adapter (drops in as the `store` arg) routes sleeve bars through the gateway; the money-path passes it at cutoff=W (backtest) and cutoff=now (live).
- **desk/weekly, desk/risk, desk/company_scan, pipeline**: universe/bars/card/catalyst reads via `serving.asof(conn)` at cutoff=now (risk's peer-catalyst check at cutoff=entry — PIT-honest, shared with backtest).
- **store.py / ingest.py**: `catalyst_version.recorded_at` = the knowable announcement date (`last_verified_at` / PIT stamp), not the ingest wall-clock.

## Deviations from Plan

**1. [Rule 1 - correctness] catalyst_version.recorded_at = last_verified_at, not now_iso().**
Plan 01 stamped the version at `now`. Wiring exposed that a HISTORICAL catalyst (ingested/backfilled today) would be gated on a 2026 wall-clock and denied at every replay week. The knowable time IS the announcement date (`last_verified_at`); stamping it there makes the bitemporal gate behaviour-equivalent to the shipped `last_verified_at<=cutoff` filter and correct for historical backfill. Updated `store._append_version` + `ingest.ingest_history` (re-stamp after verify) + simplified the synth fixture.

**2. [Rule 3 - blocking] Fixture knowable-stamp bridge.**
`build_snapshot` correctly stamps `recorded_at=now_iso()` (right for LIVE). Fixtures that fabricate HISTORICAL cohorts (synth_history, test_event_set_no_future_bar, test_weekly_runner._seed_universe) were backdated to the cohort's contemporaneous `as_of_date` so the gateway serves them at replay cutoffs — otherwise the wired reads deny a 2024 cohort on a 2026 stamp.

**3. [scope] Sleeve catalyst-classification kept unguarded.**
The plan lists routing quant/weekly's `tradeable_catalysts_light` through `book.catalysts()`. That would break the tested, deliberate design (`test_layer_a_excludes_catalyst_verified_after_as_of` relies on the sleeve's UNGUARDED catalyst-precedence to keep a future-verified catalyst out of the STAT sleeve). So the sleeve's BAR reads route through the gateway (drift-eliminating, behaviour-identical) while its catalyst-classification reads stay on the unguarded verified set. The MONEY-PATH catalyst knowability gate (trade-entry set) is fully gated via `book.catalysts()` in events.py + desk candidate selection.

## Plan-check nit #2 caveat (explicit)

- **Behaviour-preservation is byte-identical on the synthetic fixtures** (the full 1238-baseline stays green, including the hand-computed baseline + reuse-matches-recompute tests). On REAL data the swap of `last_verified_at<=eff` for the version `recorded_at<=cutoff` is a **DELIBERATE, non-leaking gate correction**: because `recorded_at` is set to `last_verified_at` at insert, the two are equivalent for verified catalysts; the one behavioural delta is **previously-NULL-verified catalysts** — the old filter's `last_verified_at is not None` check dropped them everywhere, whereas the gateway now serves them at LIVE (cutoff=now, recorded_at=now_iso() from insert) while still denying them at any past replay cutoff. This is the intended correction (a NULL-verified but status=verified catalyst is legitimately knowable now), never a look-ahead.
- **latency_cfg threading (no silent 0-lag):** the BACKTEST entry (`run_layer_a` → `build_event_set`) threads the real `latency_cfg` to the catalyst reads (the lagged class); `fill.effective_asof` RAISES on any configured-but-missing class, so there is no silent 0-lag within a supplied cfg. Bars/sleeve use `latency_cfg=None` deliberately (price bars were never latency-shifted — behaviour-preserving). The LIVE desk builds `serving.asof(conn)` with `latency_cfg=None` — an EXPLICIT, documented no-lag opt-out for this behaviour-preserving phase (the plan mandates live = current full view). The plumbing is ready (serving.asof accepts latency_cfg end-to-end); wiring a production live latency_cfg (a config-source + deliberate behaviour change denying very-recent data) is the honest next step, out of scope here.
