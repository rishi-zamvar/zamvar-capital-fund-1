## Summary

Everything load-bearing already exists. Phase 6.7 adds ONE orchestrator module (`desk/md.py`), THREE small pydantic contracts (`RetriggerFlag`, `MDDecision`, `ReconciliationRound`), a keyword-only `extra_context` pass-through on the two re-triggerable entry points, and a deterministic no-LLM `cross_check()` sheet. The two firewalls that make this safe are BOTH type-system facts, not runtime policy: (a) `RetriggerFlag(extra="forbid")` with no answer-shaped fields makes "handing the debate the answer" *unrepresentable* (mirrors how `DiligenceInput(extra="forbid")` makes WF-1/2 leakage unrepresentable), and (b) `run_diligence` still accepts ONLY `DiligenceInput`, so DD re-runs each round on sealed inputs. ### Proposed `reconcile` signature

The loop runs **per candidate** (one name), matching `run_desk` granularity — a catalyst-call gap is about *that name's* debate; a portfolio gap is about *that leg*. It receives the round-0 artifacts PLUS the raw inputs the sub-workflows need to re-run (exactly the work-item shape `run_portfolio` already consumes + `run_diligence`'s `market_data`):

```python
# desk/md.py
async def reconcile(conn, embed, item, *, max_rounds: int = 3) -> MDDecision:
    """
    item bundles round-0 artifacts + the inputs needed to RE-RUN each workflow:
      {
        "verdict":  DebateVerdict,          # WF-1 round-0
        "dossier":  StrategyDossier,        # WF-2 round-0 (carries the reconciled TradeProposal + PortfolioContext)
        "dd":       DiligenceDossier,       # WF-3 round-0
        # re-run inputs (same shapes run_desk/run_portfolio/run_diligence already take):
        "catalyst":     {...},              # run_desk(conn, catalyst) + run_portfolio item["catalyst"]
        "entry":        float,              # run_portfolio item["entry"]
        "risk_inputs":  {p_loss, gap, analog_gaps, prices},
        "dd_input":     DiligenceInput,     # SEALED — {ticker, catalyst, pair} only
        "market_data":  {...},              # run_diligence market_data
        "open_book":    [...],              # run_portfolio open_book (single-leg book for this candidate)
      }
    """
```

### Bounded-loop control (deterministic; the MD's judgment is one `run_structured` call)

```
verdict, dossier, dd = item["verdict"], item["dossier"], item["dd"]
seen_refs: set[str] = set()
rounds: list[ReconciliationRound] = []

for round_n in range(1, max_rounds + 1):
    sheet  = cross_check(verdict, dossier, dd)                      # deterministic, no LLM (Focus 4)
    review = await run_structured(_md_review_prompt(packet, sheet), MDReview, model="opus")
    #   MDReview carries: flags: list[RetriggerFlag]; satisfied: bool; response_delta: str

    disposition, converged, diverged = _classify(review, sheet, dd, seen_refs)  # deterministic §2.2
    rounds.append(ReconciliationRound(round=round_n, md_flags=review.flags,
                  response_delta=review.response_delta, convergence=_criteria(...),
                  cross_check=sheet, disposition=disposition))

    if converged or diverged or round_n == max_rounds:
        break

    for f in review.flags:
        seen_refs check -> if f.evidence_ref in seen_refs: diverged (oscillation) ; else seen_refs.add
    if any(f.target == "catalyst_call"):                            # cascade 1 -> 2 -> 3
        verdict = await run_desk(conn, item["catalyst"], extra_context=_gap_only(catalyst_flags))
        dossier = (await run_portfolio(conn, embed, [_workitem(verdict, item)], item["open_book"]))[0]
        dd      = await run_diligence(conn, item["dd_input"], market_data=item["market_data"], embed=embed)
    elif any(f.target == "portfolio_build"):                        # cascade 2 -> 3
        dossier = (await run_portfolio(conn, embed, [_workitem(verdict, item)], item["open_book"],
                                       extra_context=_gap_only(portfolio_flags)))[0]
        dd      = await run_diligence(conn, item["dd_input"], market_data=item["market_data"], embed=embed)

return await run_structured(_md_decide_prompt(packet, rounds), MDDecision, model="opus")
```

**Control rules (all deterministic, honoring decision 5 + agents-never-do-arithmetic):**
- **Cap = 3.** `range(1, max_rounds+1)`; at the cap the MD decides from `{enter, pass, escalate}` — "one more round" is unrepresentable (not a member of `MDDecision.decision`).
- **Convergence (§2.2, all of):** `dd.verdict == "go"` OR every DD residual priced in `accepted_residuals`; no new material issue (`review.flags` empty or only-refinements); cross-check sheet clean; `review.satisfied is True`. This is a Python `and` over contract fields + one MD boolean — NOT an LLM decision.
- **Oscillation → PASS:** if a `RetriggerFlag.evidence_ref` repeats across rounds (`in seen_refs`), the fix keeps un-fixing → forced PASS (decision 2). `evidence_ref` is the oscillation key precisely because it's non-empty and stable.
- **"MD can always PASS":** `pass` is always a legal terminal decision — the de-escalation valve; escalation is reserved for §4.1 factual/mandate/infra blockers only.
- **Re-run downstream after any re-trigger** (research default knob #3: full 1→2→3 on a catalyst flag; 2→3 on a portfolio flag). DD is NEVER "re-triggered with the answer" — it just re-runs on the still-sealed `dd_input`.

### Where the per-round immutable log lives

**In `MDDecision.round_log: list[ReconciliationRound]` — embedded by value in the returned contract.** This is the source of truth (immutable pydantic, extra="forbid"), and it's what the LP summary is generated FROM (decision 4, RECON-05). Optional audit persistence via the existing `kb.insert_claim` provenance seam is a thin add, not required for the phase — do not build a new store.

## Focus 2 — The 2 new contracts (+ the log record = 3)

Mirror `DiligenceInput`'s firewall exactly: `model_config = ConfigDict(extra="forbid")`, minimal fields, a validator enforcing the invariant. All go in `src/catalyst_trader/contracts/__init__.py`.

### `RetriggerFlag` — the gap-not-answer firewall, in the TYPE SYSTEM

```python
class RetriggerFlag(BaseModel):
    """The re-trigger payload into WF-1/2. extra='forbid' + the absence of any
    answer-shaped field makes 'handing the debate the conclusion' UNREPRESENTABLE —
    exactly the move DiligenceInput uses inbound (a leaked verdict is a type error at
    model_validate, not a policy check). Carries a FACT + why it's material, never a
    direction/confidence/size/verdict."""
    model_config = ConfigDict(extra="forbid")
    target: Literal["catalyst_call", "portfolio_build"]
    finding: str        # the specific fact DD surfaced that the workflow left out
    evidence_ref: str   # kb:<id> / tool:<fn>#<hash> — non-empty; ALSO the oscillation key
    why_material: str    # why it changes verdict direction / sizing bucket / structure

    @field_validator("finding", "why_material", "evidence_ref")
    @classmethod
    def _non_empty(cls, v: str) -> str:
        if not v or not v.strip():
            raise ValueError("RetriggerFlag needs a non-empty finding/why_material/evidence_ref")
        return v
```

The structural guarantee: because there is NO `direction`/`confidence`/`size`/`verdict`/`recommended_*` field and `extra="forbid"`, an attempt to smuggle the answer down is a `ValidationError` at construction — the same enforcement class as `DiligenceInput`. `_gap_only()` in `md.py` builds these from the MD review; the debate/builder re-reason from `finding + why_material` and may return **unmoved with a rebuttal** (a valid convergence outcome).

### `MDDecision` — the MD's output record (the sole decision authority)

```python
class MDDecision(BaseModel):
    model_config = ConfigDict(extra="forbid")
    decision: Literal["enter", "pass", "escalate"]
    rationale: str
    accepted_residuals: list[str] = []      # each unresolved caveat + how it's priced (size/kill/hedge) — RECON-05
    overrides: list[str] = []               # any workflow recommendation the MD overrode + reason (mandatory when overriding)
    dissent_preserved: list[str] = []       # DebateVerdict.unresolved_dissent + DD.strongest_disconfirming_evidence, VERBATIM
    round_log: list[ReconciliationRound]    # the §2.4 immutable log (Focus 1)
    # escalation-only (completed-staff-work): required iff decision=="escalate", forbidden otherwise
    blocker_class: Literal["mandate", "data_gap", "factual_conflict", "infra"] | None = None
    recommended_resolution: str | None = None

    @model_validator(mode="after")
    def _escalation_shape(self):
        if self.decision == "escalate":
            if not self.blocker_class or not (self.recommended_resolution or "").strip():
                raise ValueError("an escalation MUST carry blocker_class + recommended_resolution (completed-staff-work)")
        elif self.blocker_class or self.recommended_resolution:
            raise ValueError("blocker_class/recommended_resolution are escalation-only fields")
        return self
```

### `ReconciliationRound` — one immutable per-round record (§2.4)

```python
class ReconciliationRound(BaseModel):
    model_config = ConfigDict(extra="forbid")
    round: int                              # 1..3
    md_flags: list[RetriggerFlag] = []       # the re-trigger payload — auditable proof the answer wasn't handed down
    response_delta: str                     # what changed vs prior, or "unmoved + rebuttal"
    convergence: dict                       # each §2.2 criterion -> pass/fail (deterministic)
    cross_check: dict                       # the cross_check() snapshot the MD reviewed
    disposition: Literal["continue", "converged", "cap_hit", "diverged_pass"]
```

*(`MDReview` — the intermediate schema the MD's per-round `run_structured` returns — is a small internal model in `md.py` (flags/satisfied/response_delta); it need not be a public contract.)*

### Does `StrategyDossier` need an `MDDecision` field?

**NO — separate.** Reasons, all decisive:
1. `StrategyDossier(extra="forbid")` would *reject* an added field at validation — you'd have to edit the contract and every construction site. Avoid.
2. The MD sits ABOVE all three workflows; `MDDecision` references the packet, it is not a member of a Workflow-2 artifact. The dossier is WF-2's *proposal* (produced by `pm_decide`); the MD's decision is a distinct judgment point (decision 4 / knob #4 — do not collapse the two).
3. `MDDecision.round_log` already carries the reconciled state; the final dossier is referenced by the record, not the other way around.

So `MDDecision` is a standalone top-level contract. Keep `StrategyDossier` byte-for-byte.

## Focus 4 — Deterministic cross-check sheet (no LLM)

A pure-Python function that pre-computes inter-workflow inconsistencies off the three contracts — the artifact the MD *reviews* (agents interpret; the desk computes). Lives in `desk/md.py`.

```python
def cross_check(verdict: DebateVerdict, dossier: StrategyDossier, dd: DiligenceDossier) -> dict:
    """Deterministic consistency diff across WF-1/2/3. No LLM, no arithmetic-by-agent.
    Returns structured booleans + the offending items; the MD interprets the flags."""
```

**What it flags (all readable from the actual contract fields verified above):**

| Check | Reads | Flags when |
|-------|-------|-----------|
| `catalyst_id_consistent` | `dossier.trade.catalyst_id` vs `verdict`'s catalyst vs `dd` per-dimension catalyst_id | IDs differ → factual conflict (an upstream tool is lying — §4.1 escalation candidate) |
| `dd_vs_portfolio` | `dd.verdict` ("go"/"no_go") vs `dossier.decision` ("promote"/"kill") | DD says `no_go` while portfolio `promote`d → the core reconciliation tension the MD must resolve |
| `uncovered_red_flags` | `dd.red_flags` set-diff against `dossier.kill_criteria` + `dossier.trade.hedge` coverage | a DD red flag not answered by any kill criterion / priced residual → uncovered material risk |
| `dd_vs_risk_residuals` | `dd.residual_risks` vs `dossier` residual surface | DD residual absent from the portfolio's residual accounting → gap the MD must price or re-trigger |
| `sizing_vs_survival` | `dossier.which_risk_covered` + `dossier.residual_net_long` + `dossier.trade.size_pct` + `dossier.trade.holds_through_catalyst` | `which_risk_covered == "none"` AND non-tiny `size_pct` AND `holds_through_catalyst` → net-long uncovered exposure held THROUGH the binary |
| `direction_consistent` | `verdict.direction` vs `dossier.trade.direction` | mismatch → build drifted from the call (should never happen; regression guard) |
| `clean` | all of the above | True iff no inconsistency → feeds the deterministic convergence check |

Notes on field availability (verified against contracts): `StrategyDossier` carries `trade: TradeProposal` (has `size_pct`, `holds_through_catalyst`, `hedge`, `direction`, `catalyst_id`), `kill_criteria`, `which_risk_covered`, `residual_net_long`, `dissent_log`. `RiskAssessment.ruin_at_size` is NOT on the dossier, so `sizing_vs_survival` uses the coverage/net-long/hold-through triple that IS present (no need to thread the full RiskAssessment). `DiligenceDossier` carries `verdict`, `red_flags`, `residual_risks`, `strongest_disconfirming_evidence`, `per_dimension`.

Unit-tested exhaustively (money-critical determinism, OPS-04): clean case, each inconsistency in isolation, and the escalation-worthy `catalyst_id` mismatch.

### How `reconcile` writes it on escalate

On `MDDecision(decision="escalate")`, write atomically (tmp + `os.replace`) — a small helper in `md.py`:

```python
import json, os, time
def _write_blocker(decision: MDDecision, packet_ref: str, path=".monitor/blocker.json") -> None:
    payload = {
        "active": True,
        "title": f"MD escalation: {decision.blocker_class}",
        "detail": f"{decision.recommended_resolution}\n\nPacket: {packet_ref}",
        "options": ["confirm", "override"],   # the FRAMED choice — never an open-ended 'what should I do?'
        "since": int(time.time()),
    }
    tmp = f"{path}.tmp"
    with open(tmp, "w") as fh:
        json.dump(payload, fh)
    os.replace(tmp, path)   # atomic — the monitor may be reading concurrently
```

## Common Pitfalls

### Pitfall 1: Threading the answer down instead of the gap
**What goes wrong:** the re-trigger carries DD's verdict/direction/size → the debate rubber-stamps → independence destroyed.
**How to avoid:** `RetriggerFlag(extra="forbid")` has no answer-shaped field — it's a `ValidationError` to try. Test it explicitly (RECON-02/06).

### Pitfall 2: LLM-driven convergence / oscillation control
**What goes wrong:** letting the model decide "converged?" or "loop again?" → non-deterministic, un-auditable, can loop.
**How to avoid:** convergence is a Python `and` over contract fields + one MD boolean (`satisfied`); oscillation is `evidence_ref in seen_refs`; the cap is `range(1, max_rounds+1)`. The MD's `run_structured` returns flags + satisfied; it does NOT control the loop.

### Pitfall 3: `extra_context` default silently changing existing behavior
**What goes wrong:** injecting an empty block or reordering the prompt on the default path → regresses Phase-4/5 output.
**How to avoid:** default `None` (not `""`), guard with `if extra_context:`, and ship the byte-for-byte no-regression prompt-equality tests (Focus 3).

### Pitfall 4: Writing the live `.monitor/blocker.json` from a test
**What goes wrong:** tests overwrite the real banner file / race the monitor.
**How to avoid:** make the path an injectable arg/constant; tests pass a `tmp_path`. Production write is atomic (`os.replace`).

### Pitfall 5: `run_diligence` gaining a re-trigger param
**What goes wrong:** adding `extra_context` to DD would breach the one-directional firewall (WF-findings leaking back into DD reasoning).
**How to avoid:** DD is NEVER re-triggered with context — it only *re-runs* on the sealed `DiligenceInput`. No signature change to `run_diligence`. Test that `get_type_hints(run_diligence)` still admits only `DiligenceInput` (the DILIG-01 guard already exists — extend it).
