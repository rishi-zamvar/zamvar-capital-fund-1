The DiligenceDossier (Workflow 3) feeds UP to the MD, who reviews the whole picture (catalyst call + portfolio + diligence) and runs a BOUNDED iterative reconciliation: re-trigger Workflow 1 (debate) or Workflow 2 (builder) with the specific missing info until convergence or a hard cap, then decide. <decisions>
## Implementation Decisions (LOCKED — MD authority model + research `md-reconciliation-loop.md`)

### 1. MD authority model (governing)
Every workflow PROPOSES portfolio-impacting decisions UP to the MD, each with a full DECISION PACKET attached (catalyst verdict + kill criteria, portfolio + survival/sizing math, DD go/no-go + residual risks, conditional payoff, pre-mortem) so the MD is PURELY deciding, not gathering. Only the MD has final say (no trade decision bypasses the MD — test-enforced routing). The MD escalates to the human/LP if-and-only-if a genuine blocker it can't resolve (rare) → the monitor's decision-blocker banner. Live real-money order placement retains a final human confirmation (the one inviolable safety gate; see PROJECT.md).

### 2. Bounded reconciliation loop (research-specified)
- Round cap = 3 (PE 2–3-touch norm). Re-open ONLY on MATERIAL new info, never discomfort.
- If MD flags a CATALYST-CALL issue → re-trigger Workflow-1 debate carrying the SPECIFIC gap DD surfaced (fact + why-material, NEVER the answer — the debate re-reasons) → new verdict → portfolio builder (cascade 1→2→3).
- If MD flags a PORTFOLIO issue → back to Workflow-2 builder with the missing info → new build → back to DD for a fresh independent pass (cascade 2→3).
- Convergence = DD clears + no new material issue + MD satisfied. "Unmoved WITH a rebuttal" is a VALID convergence outcome (the MD can accept-and-commit or reject-with-reasons). Same-issue-class OSCILLATION → forced PASS. "The MD can always PASS" is the de-escalation valve.
- Per-round IMMUTABLE log (flags, re-trigger payload, response delta, disposition) for auditability.

### 3. FIREWALL PRESERVED (one-directional)
DD's INPUTS stay sealed ({ticker,catalyst,pair} only — no Workflow-1/2 reasoning in). Only DD's FINDINGS flow up to the MD and back down as "missing info"; DD re-runs independently each round. The re-trigger into Workflow 1/2 carries the gap, not the answer — enforced in the TYPE SYSTEM (the RetriggerFlag contract uses `extra="forbid"`, mirroring DiligenceInput).

### 4. Reuse discipline (research reuse-vs-new verdict — almost entirely reuse)
NEW (small): `desk/md.py::reconcile` (~150 lines, same shape as `desk/orchestrator.py`); 2 contracts `MDDecision` + `RetriggerFlag` (extra="forbid", gap-not-answer); an `extra_context` param on `debate.run`/`builder.build` (pattern already exists in `diligence.build_dimension_prompt`); a DETERMINISTIC cross-check sheet (no LLM, pre-computes inter-workflow inconsistencies). REUSE: `run_desk`/`debate.run`, `run_portfolio`/`builder.build`, `run_diligence`, the verifier/evidence primitives, the existing contracts (DebateVerdict/StrategyDossier/RiskAssessment/DiligenceDossier + OPS-01/02 memo+pre-mortem = the decision packet), the run_structured seam. LP summary is GENERATED FROM the decision record, not composed fresh.

### 4b. MD is the ROUTER for ALL flags — not only diligence (refinement 2026-08-15, RECON-08 / WEEK-06)
The weekly per-name thesis (Phase 6.5 `run_weekly`) is a REFRESH of the same standing analysis every week; when it flags something — quantitative (a metric trips vs baseline) or qualitative (an analyst notes a material change) — that flag routes UP to the MD. So `reconcile`'s input GENERALIZES beyond a single DiligenceDossier: it accepts a FLAG from any source (weekly refresh, DD, later the intra-week monitor). On a flag the MD decides whether to ACT; if so it routes to the appropriate team (WF1 debate / WF2 builder / WF3 diligence) via the SAME `RetriggerFlag` gap-not-answer mechanism + bounded loop + escalation. Unactioned flags are LOGGED, never forced. SCOPE (narrowed 2026-08-15): Phase 6.7 = the ROUTER + flag-accept ONLY, defined via the `WeeklyFlag` contract and tested with a MOCK/synthetic flag. The PRODUCER (the thing that actually emits WeeklyFlags — both quant and qual) is Phase 6.8 (the Haiku company scanner). Do NOT edit `run_weekly` / `weekly.py` in this phase.

### 5. Offline + money-safety
Fully offline: monkeypatch run_structured; zero live API in pytest. Agents interpret; the cross-check + convergence control are deterministic. Full TDD (`.venv/bin/python -m pytest`, bare python NOT on PATH). Graphify graph-first (2361 nodes, fresh).
