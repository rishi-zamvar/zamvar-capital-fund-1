# Phase 06.7 Plan 04: MD/GP Reconciliation Loop + General Flag Router Summary

**`reconcile` — the firm's decision hub and universal flag router: a thin deterministic composition over the existing run_desk/run_portfolio/run_diligence orchestrators that integrates the catalyst verdict + portfolio dossier + diligence dossier into ONE MDDecision, accepts flags from any source (act-or-log), runs a provably-bounded ≤3-round loop (MD judgment = one run_structured per round; convergence/oscillation/cascade/cap all Python), re-triggers WF-1/2 with a GAP and re-runs DD sealed, logs unactioned flags, and escalates via `.monitor/blocker.json` only on a genuine blocker.**

## Decisions Made
Implemented essentially verbatim from the plan's `<interfaces>` pseudocode. Notable resolutions within the plan's latitude:
- **Audit-integrity stamp of round_log + dissent_preserved** onto the terminal MDDecision (the model returns them as placeholders; reconcile overwrites deterministically from the record). This honors "the LP summary is generated FROM the record" and "every round in MDDecision.round_log" — the model never fabricates the immutable log. `accepted_residuals` is left as the MD's decide-time judgment.
- **`_unactioned` links incoming→actioned on `evidence_ref`** — the deterministic act-or-log link (an incoming WeeklyFlag is "actioned" iff the MD raised a RetriggerFlag sharing its evidence_ref).
- **blocker.json keeps the live 5-key schema** (blocker_class in title, recommended_resolution in detail) rather than adding keys — avoids breaking the existing monitor consumer.

## Money-Critical Invariants Enforced (tested)
- **Gap-not-answer (RECON-06):** cascade re-trigger extra_context is EXACTLY `_gap_only(...)` (built from RetriggerFlag fields, which structurally cannot hold an answer).

- **Logged, never forced (RECON-08/WEEK-06):** an unactioned incoming flag lands in `logged_flags` and triggers no re-run.
