# Phase 6.12 Plan 08: Grow + Harden the Backward Universe Summary

Captured trial-RESULT 8-Ks as day-precision `trial_readout` catalysts (the real pool-grower), widened the backward scorer to count all live-parity measurable moves, and added an absolute median-move floor plus an events/week density figure — three levers to lift the backward universe past 17 names and delete the weak ~1% tail deterministically.

## What shipped

**Task 1 — UNIV-08 (readout capture, the pool-grower).** Added 3 precise completion-anchored result phrases to `_EFTS_QUERIES` (`"topline results"`, `"met the primary endpoint"`, `"did not meet the primary endpoint"`) so result-8-Ks surface at all; added `_READOUT_RX` and a residual readout branch to `_extract`. The branch fires ONLY when PDUFA/AdCom extraction yields nothing, and only when the `filing_date` is day-precision (len==10) and `_READOUT_RX` matches the already-normalized text — emitting a single HIGH `trial_readout` candidate keyed on the filing_date. Consumers (`fetch`, `discover_edgar`, `_persist_backfill` -> `_realized_catalyst_move`) inherit it unchanged; a result-8-K now gets a real `catalyst_move` row where CT.gov month-precision readouts got zero.

**Task 2 — UNIV-09 (widen the scorer).** New shared module constant `_LIVE_PARITY_SCORE_TYPES = ("pdufa", "trial_readout", "adcom")` is the default `catalyst_types` on `_registry_moves`, `score_registry`, and `select_members`. A readout-only name and a mixed 1-pdufa+1-readout name are now scorable; the 2 existing adcom moves now count. The scorer stays ZERO-API — only the SQL IN-list widened.

**Task 3 — UNIV-10 (floor + density).** `select_members` gained `min_median_move` (default `_DEFAULT_MIN_MEDIAN_MOVE = 0.10`, overridable via `criteria["min_median_move"]`). The ranked scorable set is pre-partitioned into below/above floor; below-floor names are rejected `below_move_floor` and NEVER screened, then the percentile-cut walk fills the target from above-floor survivors. Report carries `min_median_move` + `n_below_floor`. `build_universe` gained an `edgar_years` param (threaded to `discover_candidates`) and reports zero-API `events_per_week` = sum(members' n_moves) / (edgar_years*52), with a `density_note` labeling it a backward proxy.

## Precedence capture-gap (nit 2, documented, intended)

A genuine result-8-K that ALSO contains "target action date" (or AdCom) language is classified **pdufa/adcom** — its readout move is NOT separately captured. This is the direct consequence of PDUFA/AdCom precedence and is an intended, uncommon trade-off: it avoids double-counting one filing's move and prevents misclassifying a PDUFA-acceptance 8-K (which routinely recaps trial data) as a readout. The lost case is a rare filing that both announces a fresh result and states a target-action date; its move is still measured via the PDUFA branch.

## Residual risks

- **False readout / false pdufa classification:** the phrase set is deterministic and completion-anchored, but a filing using an unusual result phrasing outside `_READOUT_RX` is missed (cite-or-drop, no false positive), and the precedence gap above trades a rare readout for pdufa. Both are conservative (no fabricated move).
- **Frugality of the 3 added efts queries:** exact-phrase, cache-served, accession-deduped — per-hit exhibit-fetch volume stays proportional to real readouts. The live re-run should still be vetted per CLAUDE.md before launch (operator runs 06.12-03).
- **Density is backward:** `events_per_week` measures historical member moves/week, not forward tradeable catalysts; it is a re-measurement proxy vs the ~1/week SELECTION goal, not a throughput promise.
