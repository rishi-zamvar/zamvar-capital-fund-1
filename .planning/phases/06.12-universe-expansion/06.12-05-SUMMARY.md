# Phase 06.12 Plan 05: Multi-Year efts + SEC Exact-Match Sponsor Resolution Summary

Widened data-driven discovery to hit the ~80-name breadth target and backfill catalyst history: the efts PDUFA pass now runs a 5-year trailing filing window (accumulating each name's full multi-year catalyst history under one CIK), and unmapped CT.gov lead sponsors resolve to tickers via SEC `company_tickers.json` using normalized-exact matching only — with near-misses and ambiguity held in the review queue, never fuzzy-attributed.

## What Was Built

### Task 1 — Multi-year efts window (UNIV-01a)
- `discover_candidates` gained `edgar_years: int = 5`: it loops `discover_edgar` over per-year trailing filing windows `[date_from - (y+1)yr, date_from - y]` and merges every year by CIK, so a company with PDUFAs across multiple years is ONE candidate accumulating ALL its catalysts (the warm-start backfill Plan 06 ingests).
- `discover_edgar` gained a keyword-only `seen_accessions` set the multi-year loop SHARES, so the same 8-K re-indexed across window edges is counted once across the whole trailing window.
- `edgar_window` (explicit tuple) still bypasses the loop for a single offline window; a single year's efts page degrading keeps the other years' candidates (never raises).
- `build_universe` switched from the 1-year `edgar_window` to the 5-year `edgar_years` default so the live path gets breadth + history.

### Task 2 — SEC exact-match sponsor resolution (UNIV-01b)
- `_norm_name`: casefold, drop periods, depunctuate, collapse whitespace, strip TRAILING corporate suffixes; distinctive biotech tokens are deliberately retained.
- `_resolve_sponsor_exact(lead, sec_map)`: exactly-one distinct `(ticker, cik)` normalized hit resolves; zero or >1 distinct → `None` → review. No fuzzy/string-distance anywhere.
- `_load_sec_map` / `_sec_map`: cached index built from `get_company_tickers(clean_name=False)`; a load failure degrades to `{}` so every unmapped sponsor routes to review.
- Wired into `_admit_ctgov_study` AFTER the curated reverse-map (Plan 01 wins first); the resolved candidate carries the same CT.gov `trial_readout` evidence + provenance, keyed by the SEC `cik_str` (ticker-recycling safe).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `get_company_tickers()` real return shape differs from the plan's stated interface**
- **Found during:** Task 2
- **Issue:** The plan interface block stated `edgar.get_company_tickers()` returns SEC rows with `title`/`ticker`/`cik_str`. The installed edgartools actually returns a pandas DataFrame with columns `[cik, ticker, exchange, company]` (loaded from a bundled parquet offline — no network). The stated row-attribute shape is not what the library produces.
- **Fix:** `_load_sec_map` iterates the DataFrame columns (`company`/`ticker`/`cik`) with `clean_name=False` (so OUR `_norm_name` is the sole normalization authority, not edgartools' own name-cleaning). The test fixture is still authored in the REAL raw SEC `company_tickers.json` shape (`{"0": {cik_str, ticker, title}}`) and the tests build a DataFrame from it to exercise the real loader path. Safety semantics (normalized-exact-only, ambiguous→review, CIK-keyed, degrade→review) are unchanged.
- **Files modified:** src/catalyst_trader/universe/discover.py, tests/test_universe_discover.py, tests/fixtures/sec_company_tickers.json
- **Commit:** feat(06.12-05) SEC resolution + test(06.12-05) SEC tests

**2. [Rule 3 - Blocking] Existing Plan-01 ctgov tests made hermetic against the SEC map**
- **Found during:** Task 2

- **Fix:** Added `monkeypatch.setattr(discover, "_SEC_MAP", {})` to the Plan-01 ctgov/merge tests so they remain unit-scoped to the curated/review logic (unmapped → review). Two merge tests also pinned an explicit `edgar_window` for single-window determinism now that the default is the 5yr loop. This preserves each test's original intent.
