<objective>
Pivot Phase 6.12 membership from FORWARD discovery + a fixed move-threshold to BACKWARD-looking proven-PDUFA-volatility percentile-cut, per the operator (live-close finding 4): forward discovery found 779 catalysts but only 200 were measurable across 47 names -> 4 admitted, because we discovered names by UPCOMING events then couldn't measure their PAST moves. Wrong direction.

Operator spec: "Pull all PDUFA filings related to public biotech stocks in the last 5 years, build a name registry. For each PDUFA event calculate the stock move and record it. Then remove the lowest percentile until we get a tradeable universe that fits our criteria. Don't worry about timing — this is just membership."

The registry + realized-move backfill ALREADY EXIST (Plans 05/06: multi-year efts -> `catalyst` table, realized moves -> `catalyst_move` table). This plan adds the BACKWARD membership layer on top of that foundation:
1. **Score each name from its PAST PDUFA moves READ FROM THE STORE** (frugal — zero API): median magnitude + frequency of big moves; require n>=2 measured events; <2 -> insufficient-history/watch list.
2. **Percentile-cut membership** — rank by vol_score, fill the target (~80) with the top scorers that also pass tradeability; N is an OUTPUT; no fixed 0.10 gate.
3. **Relax universe optionability** to "has options at all" (bid>0 both legs); the strict OI/spread gate moves to the per-trade check (already at `desk/diligence.options_liquid`).
4. **Rewire build_universe** to discover+backfill -> select_members -> build_snapshot, preserving the Blocker-1/3 fixes.

Purpose: UNIV-02b (redefined: backward percentile-cut), UNIV-02c (relaxed universe optionability), UNIV-03 (redefined: N-as-output via percentile-cut), UNIV-06 (registry reused), UNIV-07 (per-name volatility score + n>=2 eligibility + insufficient-history list). Plan 03 runs it live.
Output: the backward-membership functions + an exhaustive offline suite; the superseded fixed-threshold move gate + lambda measure-and-grow retired from the build path. NO new dep, NO migration (catalyst_move already exists).
