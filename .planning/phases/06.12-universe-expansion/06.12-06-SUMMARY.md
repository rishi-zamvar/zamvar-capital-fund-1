# Phase 6.12 Plan 06: Movement-Based Screen + Historical-Catalyst-Move Backfill Summary

Replaced the market-cap ceiling with a realized-catalyst-move screen and folded in the warm-start historical-catalyst + point-in-time move backfill: names now qualify by how much they MOVE on their catalysts (per-name median realized move >= 0.10), computed at T-1->T+2 daily granularity from a new `get_daily_bars` accessor, persisted survivorship-free with a `knowable_asof` = T+2 close date (no look-ahead) into a new additive `catalyst_move` table.

## What shipped

- **Migration 010 `catalyst_move`** — additive `CREATE TABLE` (id, catalyst_id FK->catalyst, realized_move, move_window, knowable_asof, source_grade, computed_at, `UNIQUE(catalyst_id, move_window)`). No ALTER/DROP; picked up automatically by `db.migrate`'s `*.sql` glob after 009.
- **`prices.get_daily_bars`** — the ONLY prices.py behavioral addition. Split the per-provider daily fetch into `_nasdaq_daily_bars`/`_tiingo_daily_bars` (returning the raw pre-resample daily list, tagged), which the existing `_nasdaq_daily`/`_tiingo_eod` weekly wrappers now resample over. `DAILY_PROVIDERS = [_tiingo_daily_bars, _nasdaq_daily_bars]` — the only daily-capable sources (NOT `PRICE_PROVIDERS`, whose rank-0 `_av_weekly`/`_yf_weekly` are weekly-native). `get_daily_bars` delegates to the shared `get_weekly_bars` cross-check over that subset (the daily fetchers key on the raw trade date, so no weekly bucketing runs) -> `get_weekly_bars` output is provably unchanged (parity test green).
- **Realized-move computation** — `_realized_catalyst_move(ticker, event_date, window=(-1,2))` = `abs(close(T+2)/close(T-1)-1)` from daily bars; `knowable_asof` = the T+2 close date. Future-dated (T+2 not yet closed), month/year-precision, or no-data -> `None` (never imputed). `_name_move_stat` = median.
- **Warm-start backfill** — `_persist_backfill` upserts each candidate's historical catalysts into the existing `catalyst` table (`source_origin=curated_pdufa`, `status=resolved`, idempotent by `(ticker, external_ref)` via the reused `store.insert_catalyst`) and each realized move into `catalyst_move` (idempotent by `UNIQUE(catalyst_id, move_window)`), attaching the per-name median move to the candidate.
- **Movement-based screen** — deleted `_DEFAULT_MAX_MARKET_CAP` / `_HEDGE_PEER_MAX_MARKET_CAP` and the `cap > max_cap` / hedge-peer-band gate. Kept the $200M cap FLOOR + ADV floor + size-tiny tier + the fixed optionability gate. Added: keep iff per-name median realized move >= `move_threshold` (default 0.10); a None stat -> `move_unknown` reject (cite-or-drop).
- **Rank-by-move** — `size_to_density` now ranks by `realized_move_median` (biggest movers first; live-parity catalyst count is the tiebreaker). N stays an OUTPUT.
- **build_universe** — persists the backfill BEFORE screening; keeps `min_catalyst_density=0` (Blocker-1) and `included_count` distinct from N (Blocker-2/3); summary gains `move_threshold`, `n_move_unknown`, `n_backfilled_catalysts`, `n_moves_persisted`, and per-name `realized_move_median`/`n_moves`.

## Move-metric params in effect

- `move_window = (-1, 2)` trading days (T-1 -> T+2)
- per-name statistic = `median`
- `move_threshold = 0.10` (the tuning knob; Plan 03 tunes it live)

## Deviations from Plan

### Auto-adjusted (Rule 2 - correctness/provenance)

**1. `DAILY_PROVIDERS` uses the daily-returning inner fetchers, not the plan's literal `[_tiingo_eod, _nasdaq_daily]`**
- **Found during:** Task 1
- **Issue:** `_tiingo_eod` / `_nasdaq_daily` return WEEKLY (Friday-resampled) bars. Wiring them into `get_daily_bars` would return weekly closes — the exact "silent weekly-close corruption of the screen's central metric" the plan itself warns against two sentences later.
- **Fix:** split each into a `*_daily_bars` inner fetcher (raw daily) that the weekly wrapper resamples over; `DAILY_PROVIDERS = [_tiingo_daily_bars, _nasdaq_daily_bars]`. Honors the plan's stated intent ("skip the weekly resample", "returning DAILY bars") over its literal function names.
- **Files:** src/catalyst_trader/providers/prices.py
- **Commit:** 372eb79

**2. `_realized_catalyst_move` returns a 4-tuple (added `source_grade`)**
- **Found during:** Task 2
- **Issue:** The plan documents a 3-tuple `(move, window, knowable_asof)`, but `catalyst_move.source_grade` has to be populated from somewhere; the honest value is the price-bar grade at T+2.
- **Fix:** return `(move, window, knowable_asof, source_grade)`; `_persist_backfill` writes the 4th element. Tests read it accordingly.
- **Files:** src/catalyst_trader/universe/discover.py
- **Commit:** 04b8a90
