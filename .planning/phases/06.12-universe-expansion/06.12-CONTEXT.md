<decisions>
## Implementation Decisions (LOCKED — operator-confirmed 2026-08-17)

### A. Fix the options_cboe ATM-selection bug (money-path, cross-cutting) — UNIV-02a (NEW, TDD)
- Select the LIQUID ATM pair: the strike NEAREST TO SPOT that has real liquidity (bid>0 on BOTH legs AND meaningful open interest), preferring a STANDARD MONTHLY expiry (3rd-Friday) over thin near-dated weeklies — NOT merely the earliest expiry with any bid>0 pair.
- Add regression tests on real-shape CBOE fixtures where the earliest/weekly expiry has only far-from-spot bids but a later monthly has a clean ATM pair → assert the MONTHLY ATM is chosen. Keep the Pitfall-2 junk-IV guard (no live liquid ATM anywhere → `options_quote=None` + `iv30=None`).
- This is a SHIPPED-PROVIDER fix. Verify NO regression across every consumer: existing options_cboe / build_card / diligence-gate / weekly-scanner / implied-move tests. Plan-check scrutinizes cross-consumer impact.

### B. Discovery = BOTH (breadth to ~80) — UNIV-01a + UNIV-01b (NEW)
- **Multi-year efts (UNIV-01a):** extend the efts PDUFA pass to a MULTI-YEAR trailing FILING window (default 5 years; a param). ~20 names/yr → 60-100 candidates. This DOUBLES as the warm-start historical-catalyst backfill the walk-forward needs. Dedup by CIK; a name recurring across years accumulates its catalyst history.
- **CT.gov exact-match sponsor→ticker resolution (UNIV-01b):** resolve unmapped CT.gov lead sponsors via SEC `company_tickers.json` (edgartools `get_company_tickers()` / `get_ticker_to_cik_lookup()`) using EXACT / normalized-exact match ONLY (case/punct/suffix-normalized — strip "Inc.", "Corp.", "Ltd.", "plc", etc.). Ambiguous (>1 match) or no-match → stays in the review queue (cite-or-drop; NEVER fuzzy). CIK-keyed (ticker-recycling safe). Unlocks the real US-listed biotechs (e.g. ITCI) in the 7,825-sponsor queue.

### C. Screen = average CATALYST MOVE, NOT market-cap ceiling — UNIV-02b + UNIV-06 (the key change)
- **REMOVE the market-cap ceiling entirely** (`_DEFAULT_MAX_MARKET_CAP` / `_HEDGE_PEER_MAX_MARKET_CAP` gating). Large-cap binary-catalyst biotechs (BBIO ~$15B, AXSM ~$11B, PRAX ~$10.2B) MUST qualify.
- **Add an average-catalyst-move screen (UNIV-02b):** for each candidate compute the REALIZED % move around each historical catalyst from the price cascade, keep a name only if its per-name catalyst-move statistic ≥ a MOVE THRESHOLD. Move-metric defaults (all params):
  - `move_window = (-1, +2)` trading days around `event_date` (T-1 pre-catalyst baseline close → T+2 post-catalyst settle).
  - per-catalyst realized move = `abs(close(T+2)/close(T-1) - 1)` — cumulative close-to-close over the event window (captures the binary gap regardless of which day it lands).
  - per-name statistic = `median` of the name's per-catalyst realized moves (robust to one outlier catalyst).
  - `move_threshold = 0.10` (10%) default — keep iff per-name median realized catalyst move ≥ threshold. This is the TUNING KNOB, re-set in the live run to hit a large-enough universe while excluding names that don't move enough to trade.
  - A name with NO computable historical move (no history / prices unreadable) → flagged `move_unknown` → REJECT with reason (cite-or-drop, consistent with ADV/cap None→drop), routed for review — NEVER imputed. The multi-year efts pass (B) exists precisely to give real names this history.
- **Historical-catalyst + move ingest (UNIV-06):** persist the multi-year historical catalysts (existing `catalyst` table, `source_origin='curated_pdufa'`, status `resolved`, idempotent by (ticker, external_ref)) + their computed realized moves (NEW `catalyst_move` table via migration — see D). This is the warm-start backfill + playbook seed (front half of old 7.5, now in-scope).
- Keep the ADV liquidity floor + size-tiny tier + the FIXED optionability gate (A). Keep a small market-cap FLOOR ($200M) — it removes true nano-caps ADV alone doesn't always catch (a low-priced high-volume name can clear $5M ADV yet be sub-$100M) — but NO ceiling.
- **Sizing/threshold:** measure-and-grow, ranking candidates by catalyst-move magnitude (biggest movers first), growing until the breadth/density target (~80 names / λ≈1.75-2.0 tradeable catalysts/week average — locked earlier). The move threshold is the knob set to hit a large-enough universe. N stays an OUTPUT, not hard-coded.

### D. Discipline (non-negotiable)
- FREE data only; provenance/cite-or-drop; survivorship-free + point-in-time. Historical catalyst moves are realized AFTER the catalyst — fine for a SCREEN — but STAMP point-in-time knowability (`catalyst_move.knowable_asof` = the ISO date of the T+2 close) so anything feeding the walk-forward can filter to point-in-time-knowable moves (NO look-ahead).
- Full TDD (tests before logic; real-shape fixtures offline; ZERO live API in pytest); `.venv/bin/python`; reuse the shipped providers (prices cascade, edgartools, pdufa_edgar efts primitives, options_cboe [fixed], build_snapshot/universe_as_of, store.insert_catalyst); NO new dependency.
- **MIGRATION IS NOW REQUIRED** (revises the earlier "NO migration" stance): historical catalysts reuse the existing `catalyst` table (no schema change — `curated_pdufa` origin already whitelisted), but the realized MOVES need a new `catalyst_move` table (migration 010) — the catalyst table has no move column and SQLite can't cleanly bolt point-in-time move+knowability onto it. One additive table, catalyst_id FK, `UNIQUE(catalyst_id, move_window)` for idempotent recompute.
- **Daily prices:** the move needs T-1→T+2 daily close-to-close; the cascade currently only exposes WEEKLY bars (`get_weekly_bars`), though every provider fetches daily internally before resampling. Add ONE minimal additive `get_daily_bars` accessor to `providers/prices.py` reusing the existing per-provider daily fetch + cross-check (NO rewrite). Flagged for plan-check.
- **Preserve the Blocker-1/2/3 fixes:** `build_universe` still passes `min_catalyst_density=0` to `build_snapshot` (the store-density floor stays disabled this phase — discovery's forward density + the realized-move screen are the gates; the backfilled catalyst table is for warm-start/playbook, not to re-arm the store floor, avoiding a partial-backfill empty-cohort trap); the run summary keeps `included_count` (rows actually included=1) DISTINCT from size_to_density's N; the live gate asserts on `included_count`.
- Graphify graph-first; carry `.planning/TOKEN-NOTES.md` directives (real-shape fixtures; don't babysit multi-minute live runs; plan-check ON for money phases).
