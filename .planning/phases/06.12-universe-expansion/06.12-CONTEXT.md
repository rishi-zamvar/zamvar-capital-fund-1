### B. Discovery = BOTH (breadth to ~80) — UNIV-01a + UNIV-01b (NEW)

This DOUBLES as the warm-start historical-catalyst backfill the walk-forward needs. Dedup by CIK; a name recurring across years accumulates its catalyst history.

### C. Screen = average CATALYST MOVE, NOT market-cap ceiling — UNIV-06 (registry/backfill KEPT) + UNIV-02b (fixed-threshold move screen — SUPERSEDED by decision E's percentile-cut)
*The registry + realized-move backfill (UNIV-06) + the removed market-cap ceiling STAND. The forward-discovery framing + the FIXED `move_threshold=0.10` gate + the lambda measure-and-grow are SUPERSEDED by decision E below (backward percentile-cut). Text kept for lineage.*
- **REMOVE the market-cap ceiling entirely** (`_DEFAULT_MAX_MARKET_CAP` / `_HEDGE_PEER_MAX_MARKET_CAP` gating). Large-cap binary-catalyst biotechs (BBIO ~$15B, AXSM ~$11B, PRAX ~$10.2B) MUST qualify.
- **Add an average-catalyst-move screen (UNIV-02b):** for each candidate compute the REALIZED % move around each historical catalyst from the price cascade, keep a name only if its per-name catalyst-move statistic ≥ a MOVE THRESHOLD. Move-metric defaults (all params):
  - `move_window = (-1, +2)` trading days around `event_date` (T-1 pre-catalyst baseline close → T+2 post-catalyst settle).
  - per-catalyst realized move = `abs(close(T+2)/close(T-1) - 1)` — cumulative close-to-close over the event window (captures the binary gap regardless of which day it lands).
  - per-name statistic = `median` of the name's per-catalyst realized moves (robust to one outlier catalyst).
  - `move_threshold = 0.10` (10%) default — keep iff per-name median realized catalyst move ≥ threshold. This is the TUNING KNOB, re-set in the live run to hit a large-enough universe while excluding names that don't move enough to trade.
  - A name with NO computable historical move (no history / prices unreadable) → flagged `move_unknown` → REJECT with reason (cite-or-drop, consistent with ADV/cap None→drop), routed for review — NEVER imputed. The multi-year efts pass (B) exists precisely to give real names this history.
- **Historical-catalyst + move ingest (UNIV-06):** persist the multi-year historical catalysts (existing `catalyst` table, `source_origin='curated_pdufa'`, status `resolved`, idempotent by (ticker, external_ref)) + their computed realized moves (NEW `catalyst_move` table via migration — see D). This is the warm-start backfill + playbook seed (front half of old 7.5, now in-scope).
- Keep the ADV liquidity floor + size-tiny tier + the FIXED optionability gate (A). Keep a small market-cap FLOOR ($200M) — it removes true nano-caps ADV alone doesn't always catch (a low-priced high-volume name can clear $5M ADV yet be sub-$100M) — but NO ceiling.
- **Sizing/threshold:** measure-and-grow, ranking candidates by catalyst-move magnitude (biggest movers first), growing until the breadth/density target (~80 names / λ≈1.75-2.0 tradeable catalysts/week average — locked earlier). The move threshold is the knob set to hit a large-enough universe. N stays an OUTPUT, not hard-coded.

### E. BACKWARD-looking membership — proven historical PDUFA volatility, percentile-cut (THE PIVOT) — UNIV-02b (redefined), UNIV-02c, UNIV-03 (redefined), UNIV-06, UNIV-07
Operator spec (2026-08-17): *"Pull all PDUFA filings related to public biotech stocks in the last 5 years, then build a name registry. For each PDUFA event correlating to a name, calculate the stock move and record it. Then remove the lowest percentile until we get a tradeable universe that fits our criteria. Don't worry about timing — this is just membership."*

- **Registry = the 5-yr PDUFA store (UNIV-06, reused).** The multi-year efts pass (Plan 05) + realized-move backfill (Plan 06) ALREADY persist ticker -> PDUFA events (`catalyst` table) + realized moves (`catalyst_move` table). Membership READS THIS STORE (frugality: don't re-fetch what's persisted — CLAUDE.md "save all data"). Only PAST + day-precision events have a `catalyst_move` row (future/imprecise contribute nothing — that's fine, membership is backward-only).
- **Per-name volatility score (UNIV-07):** from a name's PAST PDUFA moves — `big_move_frac` = fraction with |move| >= `big_move` (default 0.15) AND `median_move` = median(|move|); composite `vol_score = median_move * (1 + big_move_frac)` (params: big_move, formula — the calibration knob). Require **n >= 2 measured PDUFA events** (`min_events=2`) to be scorable — one event isn't a reliable read. Names with <2 measurable past events are NOT eligible; log them to a `watch/insufficient-history` list (honest — we can't judge their volatility yet; NEVER fabricate a score).
- **Percentile-cut membership (UNIV-02b redefined; N is an OUTPUT, UNIV-03 redefined):** rank scorable names by `vol_score` DESC; REMOVE THE LOWEST PERCENTILE iteratively until the surviving set that ALSO passes tradeability fits the target (~80). Implemented frugally as a measure-and-cut walk: rank desc (cheap — reads persisted moves, ZERO API), then walk down applying tradeability (free-first/cached) and admit until `target_universe_size` (default 80) is reached OR the scorable+tradeable pool is exhausted (honest under-fill — N < target reported, never padded). The effective `cut_percentile` = 1 - (N / n_scorable) is REPORTED. NO fixed `move_threshold=0.10` gate — the cut is RELATIVE (percentile), self-correcting. `target_universe_size` REPLACES `target_lambda` for membership; the lambda measure-and-grow is superseded.
- **Tradeability on the survivors (unchanged floors + one relaxation):** dollar-ADV floor (~$2-5M w/ size-tiny tier), market-cap FLOOR only (NO ceiling — decision C stands), and **optionability RELAXED to "has listed options at all" (UNIV-02c)** = a live ATM options pair with bid>0 on BOTH legs. REMOVE the OI>=100 + spread/mid<0.6 gate from `discover._optionable` (universe layer) — it false-rejected liquid names on delayed EOD quotes (INSM). The strict OI/spread liquidity check ALREADY LIVES at trade time in `desk/diligence.options_liquid` + `zero_liquidity` (per-trade, fresh quotes) — so relaxing the universe layer deletes NO guard. This DELIBERATELY reverses the earlier plan-check Blocker-2 tightening FOR THE UNIVERSE LAYER ONLY (delayed quotes make per-strike spread unreliable at build time; membership only needs "options exist") — a `# ponytail:` marker + one-line note point to the per-trade gate.
- **Ignore forward timing/calendar for membership.** Drop any "has an upcoming catalyst" requirement from the membership screen; the forward calendar (CT.gov / upcoming PDUFA) is a SEPARATE later trading-timing concern, not membership. build_universe's CT.gov forward feed is no longer a membership gate (names with no past PDUFA moves simply fail the n>=2 scorable test).
