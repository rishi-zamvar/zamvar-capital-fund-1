<objective>
Build the discovery half of `universe/discover.py` — the engine that SOURCES catalyst-dense biotech candidates from our own free data (no hand-picking), keyed by CIK for ticker-recycling safety. Two feeds, both the REVERSE of how the shipped providers run today:

1. **CT.gov (reverse-sponsor):** the shipped `clinicaltrials.fetch_trial_readouts` runs FORWARD (given known tickers, query each ticker's curated sponsor). Discovery runs it BACKWARD — query near-term interventional Ph2/Ph3 `primaryCompletionDate` broadly, take each study's `leadSponsor.name`, and reverse-map it to a ticker via the inverted `ticker_sponsor_map`. A lead sponsor not in the curated map is DROPPED to a review queue — never fuzzy-guessed to a ticker.
2. **EDGAR (unfiltered efts):** the shipped `pdufa_edgar._discover` intersects efts hits with the CURRENT universe CIK set. Discovery UN-filters it — run the same PDUFA phrase pass with NO intersection, and resolve the ticker per hit from `_source.display_names` ("Name (TICKER)") with `_source.ciks` as the CIK key. This is the primary new-name engine.

Both feeds merge into one CIK-keyed candidate dict, each candidate carrying its catalyst evidence (live-parity types ONLY: PDUFA + readout + AdCom).

Purpose: UNIV-01 — candidate discovery from our own free data. Plan 02 screens + sizes + writes; Plan 03 runs it live.
Output: the discovery functions + an exhaustive offline suite (mocked CT.gov studies JSON + efts hits JSON, real-upstream-shaped) + an extended sponsor map. NO new dependency, NO migration, NO change to the shipped providers.
</objective>
