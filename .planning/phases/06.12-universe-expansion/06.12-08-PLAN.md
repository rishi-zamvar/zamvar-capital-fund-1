<objective>
GROW + HARDEN the BACKWARD universe (Phase 6.12, new wave, money-path).

**The finding:** the backward universe came out to only 17 names because membership is scored on PDUFA moves ONLY (`_registry_moves`/`score_registry`/`select_members` default `catalyst_types=("pdufa",)`), and PDUFAs are rare (~1 per company / 1-2 yr). Only 26 names had >=2 measurable PDUFA moves, so the target-80 percentile-cut never engaged and weak movers (down to ~1% median) slipped in. Meanwhile `catalyst_move` holds 115 pdufa + 2 adcom moves and ZERO trial_readout moves — because the store's readouts come from CT.gov `primaryCompletionDate` at MONTH precision ("2026-03"), and `_realized_catalyst_move` returns None without a day-precision date.

**The fix (three levers):**
1. **UNIV-08 (the real pool-grower):** capture trial-RESULT / topline 8-Ks as DAY-PRECISION `trial_readout` events. Extend the shipped efts machinery to surface result-announcement 8-Ks (day-precision filing dates) and classify them deterministically. A result-8-K -> a `trial_readout` catalyst with event_date = the filing_date -> flows the EXISTING `_persist_backfill` -> `_realized_catalyst_move` -> `catalyst_move`, multiplying measurable events per name. CT.gov month-precision readouts stay as-is (unmeasurable — fine, not the scoring source).
2. **UNIV-09 (widen the scorer):** change the default `catalyst_types` from `("pdufa",)` to `("pdufa","trial_readout","adcom")` — count all live-parity measurable moves.
3. **UNIV-10 (hardening floor):** add a `min_median_move` floor (default 0.10) to `select_members` — a name whose median measured move is below the floor is NOT a member regardless of pool size or the percentile-cut, deleting the weak tail deterministically. Floor + cut compose: floor is an absolute gate, cut trims the rest to target.

Plus: report events/week density for the resulting universe in the run summary (the live re-run — operator runs it — reports events/week vs the ~1/week goal).

Purpose: UNIV-08 (readout capture), UNIV-09 (widen scorer), UNIV-10 (move floor).
Output: the three membership-pool changes + an exhaustive offline TDD suite + 2 real-shape fixtures. NO new dep, NO migration. Operator runs 06.12-03 live afterward.
