# Phase 6.12 Plan 07: Backward Proven-PDUFA-Volatility Membership Summary

**Membership flipped from forward-discovery + a fixed move-threshold to a BACKWARD percentile-cut over each name's proven past PDUFA volatility read from the store (zero API), with universe optionability relaxed to "has listed options at all" and the strict liquidity gate relocated to the per-trade layer.**

## Performance

- **Duration:** ~22 min
- **Tasks:** 3 of 3
- **Files modified:** 4 (1 source, 3 tests — 1 new)

## Accomplishments

### Task 1 — Relaxed optionability + tradeability-only screen
- `_optionable` now returns True on any live ATM pair with `call_bid>0 AND put_bid>0`. Dropped the `OI>=100` and `spread/mid<0.6` rejections that false-rejected obviously-liquid names on delayed EOD quotes (INSM: OI 996, delayed spread/mid 1.18). A `# ponytail:` note points to the per-trade strict gate at `desk/diligence.options_liquid` + `zero_liquidity` (fresh quotes) — no guard deleted, relocated in intent.
- `screen_candidates` is now tradeability-only: the fixed `move_threshold`/`move_unknown` gate is retired; `realized_move_median`/`n_moves` are still attached for ranking/report, never as a drop reason.

### Task 2 — Backward per-name volatility score (store-read, zero API)
- `_name_volatility(moves)` -> `{median_move, big_move_frac, n_moves, vol_score}` with `vol_score = median(|move|)*(1+big_move_frac)`, `big_move=0.15`; returns `None` when `n < min_events=2`.
- `_registry_moves(conn)` reads `catalyst_move JOIN catalyst` grouped by ticker, scoped to `catalyst_types=("pdufa",)`; only past+day-precision events have a move row, so every read value is a real measured move.
- `score_registry(conn)` -> `(scorable, insufficient)`; sub-2-event names parked with `n_moves` only (no fabricated score); empty registry degrades to `([], [])`. A monkeypatch-to-boom test proves the scorer touches no provider.

### Task 3 — select_members percentile-cut + build_universe rewire
- `select_members(conn, as_of, target_size=80, ...)` ranks scorable names by `vol_score` DESC and walks them through the tradeability screen, admitting until `target_size` is filled or the pool exhausts. `N = len(members)` is an OUTPUT (<= target); `cut_percentile = round(1 - N/n_scorable, 4)`; untradeable top-scorers are skipped (next slot fills); insufficient-history names never enter. Frugal: the lower-scoring tail is never screened.
- `build_universe` rewired to `discover_candidates + _persist_backfill (registry, unchanged) -> select_members -> build_snapshot`. Blocker-1 (`min_catalyst_density=0` passed to build_snapshot) and Blocker-3 (`included_count` distinct from `N`, reconciles with the store's `included==1` count) preserved. Summary now carries `N`, `n_scorable`, `cut_percentile`, `n_insufficient`, `insufficient_history`, per-name `vol_score`/`median_move`/`big_move_frac`/`n_moves`, plus the UNIV-05 tradeoff note.
