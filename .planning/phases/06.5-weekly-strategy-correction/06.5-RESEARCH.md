## §1 — Sizing amendment (money-critical)

### Actual current signature + the invariant it enforces
`desk/risk.py:33`:
```python
def size_for_survival(p_loss, gap=0.70, ruin_cap=0.02, per_event_cap=0.03, n_trades=52) -> ToolResult:
    # sweeps size DOWN from per_event_cap; returns the LARGEST size whose
    # risk_of_ruin(p_loss, size, gap).value <= ruin_cap. No size clears -> FLOOR (0.0005).
```
The Phase-5 test that FORBIDS a target param (`tests/test_desk_risk.py:283` → `test_no_return_target_parameter`) introspects the signature and asserts no parameter name contains `target/return/weekly/one_pct/benchmark`.

### The exact change
The existing downward sweep result IS the `survival_cap` — keep it byte-for-byte. Add an optional target-driving path on top:

```python
def size_for_survival(
    p_loss, gap=0.70, ruin_cap=0.02, per_event_cap=0.03, n_trades=52,
    *, target_return: float | None = None, expected_move: float | None = None,
) -> ToolResult:
    # 1. survival_cap = existing sweep (largest size clearing ruin_cap, <= per_event_cap). UNCHANGED.
    # 2. target_implied_size:
    #      if target_return is not None and expected_move: target/expected_move (guard >0), else FLOOR
    #    (target_return, expected_move come from the caller: the ~1% weekly target + the estimator's
    #     detail["up_move"]/expected move for the leg)
    # 3. chosen = clamp(target_implied_size, FLOOR, survival_cap)
    #    -> survival_cap is the UPPER clamp bound, so ruin_cap is structurally un-crossable.
    # 4. target_return is None -> chosen = survival_cap (byte-for-byte the Phase-5 catalyst behavior).
```
- **`target_implied_size`** = `target_return / expected_move`. To contribute ~x% of book return at a leg with expected move `m`, size ≈ x/m. The caller (risk committee / builder) passes `target_return` = the ~1% weekly target (from `select_book`'s `target_weekly`, NOT a literal) and `expected_move` = the leg's estimator move (`catalyst_move_estimate(...).detail["up_move"]` for catalyst legs; `weekly_base_rate(...).detail["mean_next"]` for statistical legs).
- **`survival_cap` stays the hard ceiling** because it is the `max=` argument to `clamp`. When the target wants more than survival allows, survival binds — provably.
- All threshold numbers (`ruin_cap`, `per_event_cap`, `target_return`) come from params/caller; no new literals in the body.

### Test #1 (INVERTED, not deleted)
`test_no_return_target_parameter` → `test_target_param_drives_size_within_survival_cap` with a pointer comment:
```python
# INVERTED in Phase 6.5 (PORT-03 amended, WEEK-04): sizing now SERVES the ~1% target WITHIN the
# survival cap. The cap remains the hard ceiling — see test_target_never_exceeds_survival_cap.
```
Asserts the signature NOW has `target_return`/`expected_move` and that supplying a large target raises the size toward (but never past) the survival cap.

### Test #2 (THE no-regression test — money-critical)
`test_target_never_exceeds_survival_cap`: over a grid of `(p_loss, gap, target_return, expected_move)`, including cases where `target_implied_size >> survival_cap`, assert:
```python

assert risk_of_ruin(p_loss, res.value, gap).value <= 0.02          # cap NEVER exceeded
assert res.value <= size_for_survival(p_loss, gap, ruin_cap=0.02).value  # <= the pure survival_cap
```
This is the acceptance gate on the whole amendment.

def select_book(candidates, open_book, weekly_budget, heat_cap, target_weekly=0.01,

## Common Pitfalls

### Pitfall 1: Assuming a price store exists
**What goes wrong:** planning `weekly_base_rate`/`classify_drop` against a non-existent OHLCV store.
**Why:** the research repeatedly says "the FMP/EOD store" / "Phase-1 store keeps delisted names" — but that is `universe_as_of` (membership), not bars. Verified: no bars table in migrations 001-004, no price fn in `store.py`, providers fetch only catalysts.
**Avoid:** make the bars store a first, gating plan item.

### Pitfall 2: Deleting the inverted invariants
**What goes wrong:** removing `test_no_return_target_parameter` / the zero-trade tests.
**Avoid:** INVERT with a pointer comment (context §1/§2 is explicit). The old behavior must stay reachable via defaults (`target_return=None`, `defensive_book=None`) so catalyst-path tests stay green.

### Pitfall 3: Breaking the ruin cap with the new target path
**What goes wrong:** a target-driven size that exceeds the survival cap.
**Avoid:** survival_cap is the `max=` bound of the clamp; the `test_target_never_exceeds_survival_cap` grid test is the gate.

### Pitfall 4: Measurement-window ≠ execution-window
**What goes wrong:** base rate measured Fri→Fri but executed Mon→Mon → the cited number is subtly wrong.
**Avoid:** one `anchor` param, used in both the tool and the runner.

### Pitfall 5: yfinance for decision data
**Avoid:** CLAUDE.md bans yfinance for anything touching trade decisions → FMP historical for the production bars store; yfinance only for throwaway sanity checks.
