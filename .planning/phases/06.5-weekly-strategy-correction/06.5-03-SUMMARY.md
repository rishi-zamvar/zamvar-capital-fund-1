# Phase 06.5 Plan 03: Weekly Thesis Engine Summary

The universe-wide weekly thesis engine (WEEK-02): one new module `quant/weekly.py` with three
deterministic, frozen-ToolResult tools — `classify_drop`, `weekly_base_rate`, `thesis_scan` — that
turn "did it drop last week?" into a cited, shrunk, cite-or-drop base rate the desk can trust. No
LLM inside any of them (agents interpret + veto downstream); fully offline on synthetic bars.

## What Was Built

- **Task 1 — `classify_drop`:** splits a name's weekly move into sector-beta vs idiosyncratic using
  the REUSED `correlation_beta` (rolling beta vs XBI over `params['weekly']['beta_window_weeks']`):
  `sector_frac = |beta*xbi_ret|/|ret|`; `|idio_ret| < sector_frac_cut*|ret|` → `sector_beta`, else a
  deterministic news gate against `store.tradeable_catalysts` landing in the drop week →
  `busted_catalyst` (down) / `positive_catalyst` (up), else `idio_no_news`. Emits a `turnover_flag`
  (latest volume vs trailing-median over `turnover_lookback`). Every threshold from `params['weekly']`
  (a missing key raises `KeyError`). This is where the info/no-info split lives (Savor 2012).
- **Task 2 — `weekly_base_rate`:** beta-binomial-shrunk conditional P(next-week-up) for a fixed-grammar
  trigger cell. Raw per-name rate is blended toward the parent (universe) cohort:
  `p_shrunk = (n_name*p_raw + k_prior*p_cohort)/(n_name+k_prior)` with `k_prior = shrink_prior_weight` —
  thin n is pulled to the cohort, ample n washes the prior out. Mirrors the `events.py` cold-start
  seam (a `shrunk` flag = `n_name < min_effective_n`). Carries `mean_next`, `median_next`, a return
  CI (`ci_low/ci_high`), `win_loss_ratio`, and the `events` dates. The measurement window is anchored
  on the SAME `params['weekly']['anchor']` the runner executes on (measurement window == execution
  window — the trap that silently evaporates the edge). Unknown trigger raises; missing param raises.
- **Task 3 — `thesis_scan`:** the weekly driver — a thesis row for EVERY universe name (a
  `no_trigger` "no measured edge" row is itself a valid, data-backed read). A row is `eligible` ONLY
  if ALL four gates hold — `p_shrunk - p_cohort >= edge_min_pts`, `n_effective >= min_effective_n`,
  `mean_next > cost_mult*roundtrip_cost`, `ci_low > 0` — AND it is not a **-15% falling-knife
  (`ret <= hard_veto_drop` → HARD VETO, any class)** and not a `busted_catalyst`. Names with a
  tradeable catalyst inside the hold window are handed to Workflow-1 (`thesis_type="catalyst"`,
  precedence). `veto_reasons` is recorded on every non-eligible row. Tools exported from
  `quant/__init__.py`.

## Deviations from Plan

Distributed-conditioning ruling (within Rule 3 — the right factoring, not a corner cut): the plan's
per-event `(trigger, drop_class, turnover)` conditioning is split across the three tools rather than
re-running full `classify_drop` on every historical week. `weekly_base_rate` conditions the
historical slice on the **trigger** (+ turnover when supplied — the primary move conditioning), while
the **info/no-info (drop_class) split is enforced at classify_drop + thesis_scan precedence**
(`busted_catalyst` is excluded from mean-reversion, so a busted-catalyst drop is never a bounce
candidate — the money-safety truth the plan requires). Full per-week drop_class re-classification of
history is a marked `# ponytail:` deferral (it needs point-in-time beta + news per historical week and
adds cost without changing the safety property). All other behavior matches the plan.

## Known Stubs

None. Two `# ponytail:`-noted honest simplifications (upgrade paths, not stubs): (1) the cohort ladder
collapses to the universe pool with a 0.5 uninformative prior when empty — the therapeutic-area
sub-cohort is a future feed; (2) the mean-return CI is a naive iid 95% interval — biotech weekly moves
cluster, so the printed n overstates effective-n; widen with a cluster-robust SE if it ever gates a
real trade. Neither affects the shipped invariants (the veto + tradeability bar are enforced on the
values computed).
