## Implementation Decisions (LOCKED — from research, HIGH confidence)

### 1. providers/pdufa_edgar.py — our own PDUFA tracker from SEC 8-K/PR
- **Discovery:** EDGAR full-text search (`efts.sec.gov/LATEST/search-index?q=%22PDUFA%22&forms=8-K`, CIK-filtered per universe) — returns ciks/display_names/adsh; NO HTML scraping. 55 in-window hits confirmed live.
- **Extraction:** fetch the matched 8-K exhibit → **deterministic regex** over the text. Verified live phrasing (2026-08-16): `PDUFA target action date {of|set for} <Month DD, YYYY>` (IMNM "April 28, 2027", CAPR "August 22, 2026"), plus `target action date of…`, `goal date of…`, AdCom `advisory committee meeting … on <date>`. Date is always `Month DD, YYYY` within ~40 chars of the keyword. **NO-LLM-dates: only emit a date that appears verbatim adjacent to a PDUFA/target-action/AdCom keyword in a real filing** (cite-or-drop; the 8-K accession URL is the authoritative provenance).
- **Emit:** `Catalyst(catalyst_type=pdufa/adcom, event_date=<extracted>, source=CatalystSource(source_name="SEC EDGAR", source_type=primary, source_url=<8-K accession url>, ...))` → flows insert→verify → **verifies as a single authoritative source (the amendment)** → tradeable-eligible.

### 2. Confidence tiers + review queue (auto-populate, human confirms)
- **HIGH confidence** (unambiguous keyword+date, single date) → auto-emit (auto-verifies via EDGAR-authoritative).
- **MEDIUM/LOW** (multiple candidate dates, fuzzy keyword) → route to the existing `load_curated_pdufa` review CSV for human confirm. Shrinks the human role from hand-typing dates to confirming auto-extracted ones from real filings.
- **Point-in-time:** `last_verified_at` / published_date from the 8-K `filing_date` (anti-look-ahead — a PDUFA is knowable the day the 8-K files).

### 3. Wire into the DAEMON path (the debug-found gap)
Wire `pdufa_edgar` into `ingest._fetch_catalysts` (runs on the daemon `run_cycle`) — NOT only `refresh.py` (the debug found `load_curated_pdufa` is not on the daemon path). Register the slot in `providers/registry.py`.

### 4. Reuse — thin build (research verdict)
REUSE: edgartools (v5.49.0), `_http` (efts fetch), the catalyst insert→verify pipeline, the `"SEC EDGAR"` entry ALREADY in `AUTHORITATIVE_SUFFICIENT` (zero verify.py change), the `load_curated_pdufa` review CSV path, the universe→CIK map (edgartools resolves CIK). BUILD: one file `providers/pdufa_edgar.py` + ~4 wiring lines. **NO verify.py edit, NO DB migration.**
