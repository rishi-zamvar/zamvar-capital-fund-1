# Phase 06.9 Plan 05: EDGAR + PDUFA Providers Summary

Two filings/catalyst providers plus one additive model field. `edgar.fetch` turns the SEC
submissions JSON into exactly the two filings signals `build_card` reads — `seen_accessions`
(the F9 offering-signal source) and `live_shelf` — fetched with the declared SEC contact-email
UA. `pdufa.fetch` merges the Federal Register documents API (GREEN/primary) and the RTTNews FDA
calendar (YELLOW/secondary, bs4-parsed) into `list[Catalyst]`, carrying the **Blocker-2 fix**: a
corroborated PDUFA/AdCom event becomes ONE `Catalyst` whose `sources` list holds BOTH
`CatalystSource`s under a shared `external_ref`, so a single `insert_catalyst` writes both rows
and the two-source verify gate can actually clear. Both providers fetch through `_http` and
degrade cleanly; zero new dependencies.

## What was built

- **`src/catalyst_trader/providers/edgar.py`** — `fetch(ticker, cik)` -> `{seen_accessions, live_shelf, provenance}` via `get_json(..., ua="sec")`. `seen_accessions` is a list of `{accession, form, filing_date}` (the two keys F9 reads plus the filing date); `live_shelf` is True iff an S-3/S-3ASR form is present. Missing CIK or a 403 degrades to `None`; an unset `SEC_USER_AGENT` surfaces the `_http` config error (never send an empty UA). Form-4/13F deferred.
- **`src/catalyst_trader/providers/pdufa.py`** — `fetch(tickers, date_from, date_to, company_map)` -> `list[Catalyst]`. FR notices attributed to a ticker via `company_map` and dated from the notice's free-text meeting date; RTTNews rows (bs4/lxml) carry ticker + drug + date + details URL. Merged per `(ticker, normalized event_date)`: both feeds -> one 2-source Catalyst; one feed -> a one-source (unverified) Catalyst. Never verifies, never sets `last_verified_at`.
- **`src/catalyst_trader/models.py`** — `CatalystSource` gains `published_date: str | None = None` (optional, additive; transport/in-memory only — not persisted, not read by verify).
- **Tests + fixtures** — `test_providers_edgar.py` (6) + `edgar_submissions.json`; `test_providers_pdufa.py` (6) + `fedregister.json` + `rttnews.html`. All offline via pytest-httpx.

## Blocker-2 correctness (verified)

- **(a) pdufa merges FR+RTTNews into ONE 2-source Catalyst** — `test_pdufa_merges_two_sources_same_event`: the KURA/Ziftomenib event reported by BOTH feeds yields a single `Catalyst` whose `sources` list is exactly `[primary, secondary]`, both `agrees=True`, under one `external_ref` — so `len(agreeing) >= 2 and has_primary` is satisfiable after `insert_catalyst`. A single-feed event (`test_pdufa_single_source_stays_one_source`, the FR-only Cardiodex notice) stays one-source and `status == unverified` (cite-or-drop, never forced tradeable).
- **(b) `published_date` added optional/default-None without breaking existing CatalystSource constructions** — `grep -n published_date src/catalyst_trader/models.py` shows the field; the full suite (972 passed) confirms every existing `CatalystSource(...)` still constructs. `test_pdufa_fr_source_carries_publication_date`: the FR source's `published_date == "2026-08-10"` and is DISTINCT from `reported_date`/`event_date == "2026-11-14"`; the RTTNews source leaves it `None`.
- **(c) the provider never sets `last_verified_at`** — `test_pdufa_does_not_set_last_verified_at` asserts every emitted Catalyst has `last_verified_at is None`. No assignment exists in `pdufa.py` (the three `last_verified_at` grep hits are the module docstring + explanatory comments documenting the Pitfall-4 intent, not code that sets it).
- **(d) EDGAR emits only seen_accessions + live_shelf with the SEC UA** — `test_edgar_extracts_accessions_and_shelf` + `test_edgar_sends_sec_ua`: the return dict is scoped to those two fields (+ provenance), no Form-4/13F, and the captured request carries the declared `settings.sec_user_agent` header with the 10-digit zero-padded CIK.

## Deviations from Plan

### Auto-adjusted (documented, no user gate)

**1. [Rule 3 - Source contradiction resolved] FR `date_type` is `estimated`, not `confirmed`.**
- **Found during:** Task 2. The plan interface note said the FR source is `date_type=confirmed`, but `models.DateType` has only `estimated` / `actual` (DB CHECK-constrained), no `confirmed`.
- **Resolution:** used `DateType.estimated` for BOTH sources — a PDUFA/AdCom date is an announced target, not a realized event, exactly as `verify.load_curated_pdufa` already documents. The primary/secondary authority distinction (what the verify gate actually reads) is carried by `source_type`, not `date_type`. Reported rather than silently guessed on a money path.
- **Files:** `src/catalyst_trader/providers/pdufa.py`.

**2. [Rule 3 - Scope] `source_origin` reuses the existing `curated_pdufa` enum.**
- **Reason:** `Catalyst.source_origin` is DB-CHECK-constrained to 4 values; adding `federal_register`/`rttnews` would need a new enum + a migration, outside this plan's file-disjoint scope. `curated_pdufa` is the semantic PDUFA/AdCom bucket.
- **Files:** `src/catalyst_trader/providers/pdufa.py`.

**3. [Rule 3 - Blocking] FR `fields[]` param passed as a tuple.**
- **Found during:** Task 2 — a list value made the `_http` cache key unhashable (`TypeError`). A tuple repeats identically in httpx and is hashable. One-line fix.

### Note on the `last_verified_at` acceptance grep
The plan's acceptance/verification says `grep -n last_verified_at src/.../pdufa.py` should be empty. It is non-empty here, but ONLY because of the module docstring + comments that document the Pitfall-4 rule ("does NOT set last_verified_at"). There is no code that assigns it; the behavior is proven by `test_pdufa_does_not_set_last_verified_at`. Kept the documentation over gaming the grep.
