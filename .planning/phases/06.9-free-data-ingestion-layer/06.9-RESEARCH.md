## Summary

Every downstream consumer already reads its data from the **store** (`bars_asof`, `card_asof`, `tradeable_catalysts`) or from an **injected `raw` dict** (`build_card`). Nothing in `run_weekly`, `thesis_scan`, `run_scan`, or the backtest engine fetches anything itself. That is the whole reason INGEST-03 ("zero downstream contract change") is cheap: **the store IS the seam.** In offline tests, fixtures populate the store (`upsert_bars(source="fixture")`) and hand-built `raw` dicts feed `build_card`; in live mode, an ingestion step populates the *same store rows* from real providers and an `assemble_raw()` builds the *same `raw` dict*. There is no boolean toggle to thread through the desk — the toggle is simply *who writes the rows*.

So the phase is: (1) build per-source fetch functions + one shared `_http` cache/rate-limit/retry base; (2) an `assemble_raw()` + a historical-ingestion entrypoint that funnel provider output through the **existing** UPSERT write-paths; (3) test every provider fully offline (`pytest-httpx` for httpx sources, an injectable downloader for yfinance); (4) a separate, documented, explicitly-network **shakedown** script that ingests real data and runs the real backtest + scan.

**Primary recommendation:** Build ~6 stateless provider modules + one `providers/_http.py` base + one `ingest.py` (assemble_raw + historical loop, wired to existing store UPSERTs) + one `scripts/shakedown` network run. Reuse *every* read path and store write-path unchanged. Provenance: catalysts already carry it via `CatalystSource`; for bars/cards add a lightweight envelope (see Provenance decision). Zero new pip dependencies — `httpx`, `yfinance 1.6.0`, `pandas 3.0.5`, `bs4 4.15.0`, `lxml`, `pytest-httpx` are all installed.

### Pattern 1 — The provider interface split + provenance envelope
**What:** Two provider shapes, unified only by the provenance rule.
- **Catalyst providers** (`pdufa.py`, `clinicaltrials.py`, `fmp.py`): return `list[Catalyst]`, provenance = attached `CatalystSource(source_name, source_url, source_type, reported_date, date_type, retrieved_at)`. Fit `base.Provider`. Flow into `insert_catalyst` → verify pipeline.
- **Datum providers** (`prices.py`, `options_cboe.py`, `finra.py`, `edgar.py`): return provenance-tagged dicts / bar lists. `prices` → `upsert_bars`. The rest → fields in the `assemble_raw` `raw` dict.

**Provenance decision (Claude's discretion — lean default):**
- Catalysts: DONE via `CatalystSource` (no work).
- **Cards:** embed a `provenance` sub-dict inside the card JSON — e.g. `card["provenance"] = {"iv30": {"source_url": ..., "fetch_ts": ..., "grade": "yellow"}, ...}`. No migration (card is already one JSON TEXT column). **Recommended** — cheapest, honors the invariant.
- **Bars:** `upsert_bars(..., source=...)` already records `source` + `retrieved_at` (= fetch_ts). Grade is uniform per source (yfinance = YELLOW), so encode it in the `source` string (`"yfinance"`, documented YELLOW) rather than a per-bar column. A migration 007 adding `source_url`/`source_grade` columns to `price_bar` is available if the planner wants per-row columnar provenance, but is over-engineering for a single-source column (ponytail: skip until a query needs it).

**When to use:** every persisted datum. Anything lacking a citable URL+timestamp is dropped (degrade), never imputed.

### Pattern 2 — The `_http` base (cache + rate-limit + retry + degrade)
**What:** One shared helper all httpx providers call.
- **Cache-first:** per-`(source, key)` cache with **≥5-min TTL** intraday, 24h for calendars, publication-schedule for FINRA. Never refetch inside TTL (research §5.4). `@lru_cache`/`functools` won't carry a TTL — a tiny dict-of-`(value, expiry)` or `cachetools.TTLCache` (not installed → use a ~10-line dict cache; ponytail: don't add a dep).
- **Rate:** ≤1 req/sec per host, jittered, sequential per host.
- **Retry:** `httpx.HTTPTransport(retries=2)` (same as `fmp.py`/`clinicaltrials.py`).
- **UA:** browser UA for YELLOW endpoints (CBOE/Nasdaq/RTTNews need it); **SEC requires a declared UA with contact email** — read from `config.settings` (add `sec_user_agent` env field; env-first).
- **Degrade:** on 403 / structure-change / timeout → mark source degraded, return `None`/empty, let the caller fall through the ranked fallbacks (each need has ≥2 sources). **Never raise into the pipeline; never fabricate.**

**When to use:** CBOE, FINRA, EDGAR, Federal Register, RTTNews. yfinance is a library call, not an `_http` target.

### Pattern 3 — The store IS the seam (INGEST-03, the key finding)
**What:** Zero downstream contract change because nothing downstream fetches. Two seam points:
1. **Store rows** (bars/catalysts/cards): fixtures write them in tests; the live ingestion writes the *same rows* via the *same* `upsert_bars`/`insert_catalyst`/`write_card`. `thesis_scan`, `run_layer_a`, `build_event_set`, `run_scan` read the store agnostically — unchanged.
2. **The `raw` dict** for `build_card`: tests pass it literally; live builds it via `assemble_raw(providers, ticker, week_end)` from CBOE/FINRA/EDGAR/catalyst providers.

**Anti-pattern to avoid:** threading a `live=True/False` boolean through `run_weekly`/`thesis_scan`/`build_card`. Unnecessary — the toggle is *which code populates the store/`raw`*, resolved at the entrypoint, not inside the desk. (This is MORE reuse than CONTEXT decision #3's "seam toggle" language implied; flag to planner as the phase-shrinking finding.)

### Pattern 4 — Historical ingestion + idempotency (INGEST-04)
**What:** `ingest.py` reads `data/seed_universe.csv` (24 names + XBI/LABD; `delisted` column present) and for the ~1-2yr window:
- yfinance weekly bars per ticker → `upsert_bars(conn, tk, bars, delisted=<seed row>, source="yfinance")`.
- Catalysts: `clinicaltrials.fetch_trial_readouts` + `fmp.fetch_earnings` + `pdufa.fetch` → `insert_catalyst` (each flows through the existing insert→verify two-source gate).
- Cards: `assemble_raw` + `build_card` + `write_card` per (ticker, week_end).
- **Idempotent by construction** — all three write-paths UPSERT on natural keys; re-running never duplicates.
- **Point-in-time + survivorship:** `upsert_bars(delisted=...)` retains delisted history; universe snapshots are append-only (`universe.build`); all reads use the `week_end <= as_of` guard.

**When to use:** the one-time/periodic bulk load before a shakedown or backtest.

### Pattern 5 — Live shakedown boundary (INGEST-05)
**What:** `scripts/shakedown.py` — an **explicit network run**, NOT a pytest test:
1. Live-ingest the real seed universe (Pattern 4, network on).
2. Run `run_layer_a` (backtest) + `thesis_scan` on the ingested real data end-to-end.
3. Log every edge case (illiquid names, missing bars, stale sources, delisting, ticker mismatches, holiday/tz gaps, rate-limit hits) to a report artifact.
4. Triage: fix money-critical breaks now; log the rest.
Documented run command: `.venv/bin/python -m scripts.shakedown` (or a `cli.py` subcommand). The offline pytest suite proves the *wiring* against fixtures (see Validation Architecture); the live run is the real-data stress test.

## Common Pitfalls

### Pitfall 1: yfinance returns split/dividend-ADJUSTED prices as-of NOW (silent look-ahead)
**What goes wrong:** `yf.download(auto_adjust=True)` (the 1.6.0 default) back-adjusts the whole series to *today's* corporate-action state. A bar's "close" for 2025-06 reflects splits/divs that happened *after* it — a point-in-time backtest reading it sees information that didn't exist at that week's `as_of`.
**Why it happens:** yfinance adjusts for the current view, not as-reported.
**How to avoid:** decide the adjustment policy explicitly and document it (raw `Close` vs adjusted `Adj Close`; for a weekly-return biotech backtest, adjusted is usually fine but the *choice* must be conscious). Store the policy in the bar `source` provenance. Flag to planner as a money-critical decision.
**Warning signs:** backtest returns diverge from `free-data-sources.md` expectations near known split/dividend dates.

### Pitfall 2: CBOE `iv: 0.0` on deep-ITM/no-quote contracts (garbage IV)
**What goes wrong:** ingesting junk IV off illiquid/stale contracts.
**How to avoid:** filter to near-the-money contracts with live `bid>0` before trusting IV; run the existing liquidity gate (`options_liquid`), and on fail tag `options_data: none/illiquid` and fall back to the in-house estimator (research §1.9). Never let junk IV reach the model.
**Warning signs:** IV=0 or straddle mid computed off last-trade on thin names.

### Pitfall 3: YELLOW-source UA / bot walls (CBOE, Nasdaq, RTTNews, SEC UA)
**What goes wrong:** plain requests get 403 or an empty shell; SEC blocks a missing/empty UA.
**How to avoid:** browser UA for YELLOW endpoints; **declared UA with contact email for SEC** (env-first, `settings.sec_user_agent`), ≤10 req/sec SEC. Respect the degrade path on 403.
**Warning signs:** 403s, HTML fingerprint/redirect gates (BioPharmaCatalyst-class — those are deferred Tier-B).

### Pitfall 4: `tradeable_catalysts` has NO as-of guard (backtest look-ahead)
**What goes wrong:** a catalyst *verified after* the simulated week is visible in the event set.
**How to avoid:** already handled in `build_event_set` (it post-filters `last_verified_at <= eff`) — but **any new PDUFA catalyst ingested must set `last_verified_at` correctly** so that guard works. Ingested PDUFA dates flow through the verify pipeline (two-source gate); don't bypass it. (This exact class of leak was the Phase-7 plan-check catch.)
**Warning signs:** ingested PDUFA rows with null/future `last_verified_at` appearing in past event windows.

### Pitfall 5: FINRA sort requires an EQUAL filter on the partition key
**What goes wrong:** querying FINRA `consolidatedShortInterest` without an `EQUAL` filter on `settlementDate` fails/returns unsorted.
**How to avoid:** query by explicit settlement date (15th & EOM, published ~T+9 business days) — research §3.1 gotcha, verified live. Store staleness honestly (bi-monthly cadence).

### Pitfall 6: RTTNews is editorial (confirm before trading)
**What goes wrong:** trusting an RTTNews PDUFA date as authoritative.
**How to avoid:** RTTNews is a **discovery** feed (YELLOW). Federal Register (GREEN) covers AdCom authoritatively; company PR/8-K via EDGAR is the confirmation step. cite-or-drop: a tradeable date needs its authoritative confirmation source, not just the RTTNews row.
