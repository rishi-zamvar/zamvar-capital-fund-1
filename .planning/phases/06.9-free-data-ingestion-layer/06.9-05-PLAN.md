<objective>
Build the two filings/catalyst providers:
- `edgar.py` — SEC EDGAR submissions -> `{seen_accessions, live_shelf}` (the ONLY fields `build_card` consumes) + provenance, fetched with the declared SEC UA. Form-4 / 13F are DEFERRED (no consumer yet — YAGNI, RESEARCH Open Q3).
- `pdufa.py` — Federal Register API (GREEN JSON) + RTTNews (YELLOW HTML scrape via bs4) -> `list[Catalyst]`. For a PDUFA/AdCom event that BOTH feeds report, it emits ONE Catalyst carrying BOTH `CatalystSource`s (FR primary/confirmed + RTTNews secondary/estimated) — this is what lets the downstream two-source verify gate reach >=2 agreeing + a primary. A single-source event emits a one-source Catalyst that stays unverified (cite-or-drop, never forced). The FR source carries its document publication_date so ingest can stamp `last_verified_at` point-in-time. The provider does NOT verify and does NOT set `last_verified_at` (Pitfall 4); RTTNews is discovery-only (Pitfall 6).

Purpose: the filings signals for the card (INGEST-01) + the PDUFA/AdCom catalyst feed that can actually clear the two-source gate, both under INGEST-02 discipline.
Output: one optional model field + two providers + offline suites. File-disjoint from the other Wave-2 plans (parallel; the models.py addition is a single additive optional field).
</objective>

Catalyst provenance model (models.py L54-78) — pdufa emits these, mirroring clinicaltrials.py:
```python
class CatalystSource(BaseModel):
    source_name: str
    source_url: str | None = None    # cite-or-drop
    source_type: SourceType          # SourceType.primary (FedRegister) / .secondary (RTTNews discovery)
    reported_date: str               # the date THIS source CLAIMS for the event (the PDUFA/AdCom date) — NOT a publication date
    date_type: DateType = DateType.estimated   # .confirmed (FedRegister) / .estimated (RTTNews)
    agrees: bool = True              # verify_catalyst counts agreeing sources
    retrieved_at: str                # when WE fetched it (not the publication date)
    # ADD (this plan): published_date: str | None = None
    #   the source's OWN publication date (for FR: the Federal Register document publication_date).
    #   Transport/in-memory only — NOT persisted, NOT used by verify; ingest (Plan 07) reads it off the
    #   in-memory Catalyst to stamp last_verified_at point-in-time. Default None (RTTNews leaves it None).
class Catalyst(BaseModel):
    ...                              # ticker, catalyst_type, event_date, external_ref, etc.
    last_verified_at: str | None = None   # DO NOT set in the provider — the verify/ingest path owns it (Pitfall 4)
    sources: list[CatalystSource]         # a corroborated event -> BOTH sources in this list
```
clinicaltrials.py is the pattern to mirror (builds CatalystSource then returns Catalyst).

IMPORTANT — why the merge matters (verified against source):
- `verify_catalyst` (calendar/verify.py L46-61) marks a catalyst verified iff `len(agreeing) >= 2 and has_primary`.
- `insert_catalyst` (store.py L88-112) DELETEs + replaces the source rows for the same `(ticker, external_ref)`. So emitting FR and RTTNews as TWO SEPARATE Catalyst objects with the same external_ref makes the second overwrite the first's sources -> neither ever reaches 2 agreeing. The FIX is to merge both sources into ONE Catalyst.sources list HERE, so a single insert writes both source rows. (No store.py change needed.)

Merge key: the SAME event = (ticker, normalized event_date, drug/external_ref). Match an FR notice to an RTTNews row on that key; combine into one Catalyst(sources=[FR_primary, RTTNews_secondary]) with a shared deterministic external_ref (so re-runs stay idempotent). Only-FR or only-RTTNews -> a one-source Catalyst (stays unverified).
