<objective>
Build the single most money-critical function in the phase: derive a catalyst's date precision and uncertainty type from the source data's own precision — never from a guess, never by coercing a partial date to a false-precision day. RESEARCH proved ~35% of live CT.gov dates are month-only; treating `2027-04` as `2027-04-01` is a total-loss vector. This plan is TDD by mandate: the exhaustive edge-case suite is written and RED before the classifier exists.

Purpose: DATA-04 (uncertainty typing) is not a labelling opinion — it is a fact about how precisely the source knows the date. This module encodes that fact and every downstream plan (providers, verify) calls it.
Output: `dates.py` with `parse_precision` + `classify`, backed by an exhaustive test suite.
</objective>
