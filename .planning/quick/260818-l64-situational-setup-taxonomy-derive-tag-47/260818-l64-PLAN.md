<objective>
Make SITUATIONAL SETUP an explicit, retrievable axis of the warm playbook. Today `analog_query`
keys on disease/mechanism + the ticker string, so it clusters by identity, not by the setup
(priced-in, single-asset-binary, first-in-class, financing-overhang, ...) — which is the axis that
actually transfers to a fresh event. This plan:

1. Freezes the LOCKED taxonomy (16 tags, 12 ex-ante + 4 outcome + rubric) into `data/`.
2. Builds a deterministic, keyword/regex tagger (NO LLM) that stamps a `setups` list onto each
   catalyst node from its narrative fields.
3. Wires `setups` into retrieval as a CANDIDATE FILTER so setup-matched precedents in OTHER
   indications become reachable, and drops the ticker from the query context.
4. Ships a committed before/after retrieval stress harness.

Purpose: turn a stress-test finding (retrieval clusters on identity, not setup) into a fix.
Output: a frozen vocab, a tested tagger, a setup-aware retrieval path, and a stress harness.

RETRIEVAL-MECHANISM DECISION (the plan makes the call the goal asked for, and justifies it):
Chosen = (a) setup-membership CANDIDATE FILTER via a generic list-membership extension to
`_structural_filter` (json_each any-overlap), + deepen `analog_query`'s over-fetch when a list
filter is active so setup-matched-but-disease-distant precedents are actually ranked, + drop the
ticker from `_analog_context`.
- Rejected (b) "re-embed setup tags into the card only": the offline test embedder `kb.hash_embed`
  is LEXICAL (whole-string sha256, not bag-of-words), so a shared setup token would NOT create
  vector proximity under it — the setup improvement would be UNVERIFIABLE in-memory, violating the
  no-live-DB test constraint. (A future real-embedder re-embed can layer on top; not required here.)
- Rejected pure (c) "rerank a fixed KNN pool by setup-overlap": the goal's explicit trap — a global
  top-(k*4) KNN never returns a cross-disease setup match, so rerank can't surface it. The FILTER
  puts it in the candidate pool; deepening the fetch within the filtered pool makes it rankable.
</objective>
