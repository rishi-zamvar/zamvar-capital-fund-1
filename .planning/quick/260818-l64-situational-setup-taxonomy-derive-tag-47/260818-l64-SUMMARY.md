# Phase quick-260818-l64: Situational-Setup Taxonomy + Deterministic Tagger + Setup-Aware Retrieval Summary

Made SITUATIONAL SETUP an explicit, retrievable axis of the warm playbook: froze the 16-tag vocab into the repo, built an LLM-free regex tagger that stamps a multi-label `setups` list onto each catalyst, extended `analog_query` to filter + reach cross-disease setup siblings, dropped the ticker from the query context, and shipped a before/after retrieval stress harness. Code Tasks 1-3 are done and green offline; Task 4 (live tag of the 470 real nodes + real before/after run against the gitignored `catalyst.db`) is left for the orchestrator to run in the MAIN working dir.

## Retrieval mechanism chosen (and why)

Chosen = **(a) setup-membership CANDIDATE FILTER** via a generic list-membership extension to `_structural_filter` (`json_each` any-overlap), plus deepening `analog_query`'s over-fetch to the full vec set when a list filter is active so setup-matched-but-disease-distant precedents are actually rankable, plus dropping the ticker from `_analog_context`.

- **Rejected (b) "re-embed setup tags into the card"**: the offline test embedder `kb.hash_embed` is LEXICAL (whole-string sha256), so a shared setup token creates NO vector proximity under it — the improvement would be unverifiable in-memory, violating the no-live-DB test constraint. (`setups` is therefore a STRUCTURAL axis, not embedded; a future real-embedder re-embed can layer on top.)
- **Rejected pure (c) "rerank a fixed KNN pool"**: a global top-(k*4) KNN never returns a cross-disease setup match, so a rerank can't surface it. The FILTER puts it in the candidate pool; deepening the fetch within the filtered pool makes it rankable.

## What was built (Tasks 1-3)

**Task 1 — frozen taxonomy + deterministic tagger** (`data/setup_taxonomy.json`, `playbook/tagger.py`, `tests/test_setup_tagger.py`)
- `data/setup_taxonomy.json`: the LOCKED 16-tag vocab (12 ex-ante + 4 outcome) + `tagging_rubric` + per-tag `ex_ante_cues`, committed verbatim.
- `tagger.py`: `load_taxonomy()` (cached, resolves `<repo-root>/data/setup_taxonomy.json` via `parents[3]`), `tag_setups(fields)->list[str]` (pure, multi-label, taxonomy-declaration-order stable, `[]` on no match), `tag_all_catalyst_nodes(conn)->{total,with_ex_ante,coverage}` (idempotent in-place UPDATE of a json-each-filterable `setups` list; no re-embed). The deterministic rubric = one case-insensitive alternation per tag; an import-time check asserts `_TAG_PATTERNS` keys == taxonomy tag names so a widened vocab can't silently under-tag.

**Task 2 — setup-aware retrieval** (`kb.py`, `desk/builder.py`, `tests/test_kb_setups.py`)
- `_structural_filter`: generic list-membership (no fork) — a LIST value matches any candidate whose `$.key` (scalar OR json array) overlaps via `json_each`; a SCALAR value keeps exact match AND allows list-attr membership. Scalar path is byte-for-byte for existing callers.
- `analog_query`: when any filter value is a list, over-fetch the full `kb_vec` set (sub-ms at this scale) so a cross-disease setup sibling is never truncated out of the global top k*4.
- `setup_filters(conn, ctype, setups, min_analogs=5)`: thinness gate — adds `{"setups":...}` only when the type+setups cohort has >= min_analogs, else type-only; None/empty -> type-only.
- `builder.build`: tags the query event, filters on setups, threads `filters` into the analog cite ref; `_analog_context(verdict, ctype)` drops the ticker (identity-clustering removed).

**Task 3 — before/after stress harness** (`scripts/retrieval_stress.py`, `tests/test_retrieval_stress.py`)
- Pure `_overlap(query_setups, result_setups)->int` and `_aggregate(per_cid)->{mean_overlap_before, mean_overlap_after, n}` (unit-tested offline, no DB).
- Live `main()`: per held-out cid runs analog_query BEFORE (type-only) and AFTER (setup-aware), emits a JSON report; `--help` and all DB access are guarded so import/`--help` never opens a DB.
